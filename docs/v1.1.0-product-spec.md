# CoDesign Agent v1.1.0 产品说明

> **把设计过程变成一棵可以继续生长、回溯和复盘的思维树。**

**产品名称**：CoDesign Agent  
**版本**：v1.1.0  
**发布日期**：2026-07-31  
**版本主题**：思维树结构重构、阶段生命周期重构、资源卡问题节点化  
**适用平台**：iPadOS / iOS / macOS（Designed for iPad）

---

## 1. 版本定位

v1.1.0 是一次面向思维树核心语义的结构升级。它重新明确了三件事：

1. **Stage 是阶段封口节点，不是阶段开始时就固定出现的容器。**
2. **回溯是真正的二叉分支，旧路径和新路径都属于设计过程证据。**
3. **资源卡属于一个确定的问题节点，不再作为独立的全局树节点或远距离列展示。**

因此，v1.1.0 的思维树从“阶段列表 + 资源列”转为“从项目种子向上生长的设计推理树”：问题、回答、回溯、阶段完成和资源依据都在同一套结构中表达，同时继续保留原有的批注、持久化和项目包迁移能力。

---

## 2. 用户可以获得什么

### 2.1 更符合设计过程的阶段推进

进行中的 Stage 是开放生长的提问空间。用户可以继续回答、查看问题详情、回溯或修正判断，Stage 卡片不会提前占据画布。

只有当当前 Stage 真正完成后，系统才会在该阶段当前有效叶节点的正上方生成阶段封口卡片。下一阶段从这张封口卡片上方继续生长。

### 2.2 可解释的回溯关系

发生回溯后：

- 左侧保留被替代的旧分支；
- 右侧生成修改后的新分支；
- 旧分支使用低强调灰色和虚线；
- 新分支使用主色和实线；
- 后续问题沿右侧当前有效主干继续生成；
- 当前主干可以横向移动，不再被强制拉回画布中心。

旧分支不会被删除。它保留了方案为什么改变、哪些判断被放弃以及回溯发生在哪里等过程证据。

### 2.3 问题节点上的资源卡

方法卡、论文卡、案例卡、设计原则卡和课程框架卡现在都绑定到一个明确的问题节点。

默认状态下，资源卡收纳在问题节点后方，只显示错位边缘和数量提示。用户向右拖动问题节点后，属于该问题的资源卡在同一水平线上依次展开；再次向左拖动即可收回。

资源卡的批注、详情和绑定问题跟随卡组一起工作，不再出现资源卡离开所属问题、形成独立纵列或制造远距离连接线的情况。

### 2.4 跨阶段信息不会强行跳阶段

如果用户在 Stage 1 的回答中提到了 Stage 4 的内容，系统会先将其作为“待该阶段确认”的候选信息保留在审计记录中，不会直接点亮 Stage 4 或跳过中间阶段。

当真正进入 Stage 4 后，系统会通过澄清问题重新确认该信息。只有用户确认无误，信息才会写入对应 Brief 字段并参与该阶段完成判定。

## 3. 核心用户流程

```text
项目种子
  ↑
当前 Stage 的问题节点
  ↑
回答、方法依据与设计判断
  ↑
必要时回溯：左旧分支 / 右新分支
  ↑
当前有效叶节点
  ↑
Stage 完成封口卡片
  ↑
下一 Stage 的问题树
```

一轮典型使用过程如下：

1. 用户创建项目并输入一个模糊的设计想法。
2. 工作台提出当前 Stage 的一个核心澄清问题。
3. AI 同时保存完整问题和适合思维树展示的概括问题。
4. 用户回答后，问题节点、Brief 字段、学习轨迹和资源绑定同步更新。
5. 用户可点击节点查看完整问题、回答、依据和批注，也可从节点发起回溯。
6. 回溯后旧路径左置并降权，新路径右置并成为 active branch。
7. 当前 Stage 完成后生成封口卡片，并允许该 Stage 整体收起。
8. 下一 Stage 从上一张封口卡片上方继续生长。

## 4. 思维树产品语义

### 4.1 Stage 生命周期

每个 Stage 在思维树中具有三种等价业务状态：

| 状态 | 画布表现 | 允许的操作 |
|---|---|---|
| `inProgress` | 只显示该阶段的问题与必要分支，不显示 Stage 封口卡片 | 继续提问、回答、点击详情、回溯、展开问题资源卡 |
| `completedExpanded` | 显示封口卡片和完整阶段子树 | 查看、点击、回溯历史、收起 Stage |
| `completedCollapsed` | 只保留封口卡片 | 展开 Stage，恢复完整子树 |

进行中的 Stage 不允许整体折叠，也不显示阶段级收起按钮。完成后的 Stage 才能收起；收起只改变可视投影，不删除节点、资源卡或批注。

### 4.2 Stage 封口卡片

Stage 封口卡片表达“阶段完成标记 + 阶段摘要 + 阶段子树收纳入口”。

它不再：

- 在阶段开始时预生成；
- 固定在画布顶部或中心；
- 使用项目种子的横坐标；
- 使用旧分支或左右分支的几何中点。

完成时，系统找到当前 Stage active branch 中拓扑位置最靠上的问题节点，并采用以下定位规则：

```swift
stageCard.centerX = activeLeaf.centerX
stageCard.bottomY = activeLeaf.topY - stageCardGap
```

Stage 卡片与 active leaf 通过主色实线连接。回溯后如果 active leaf 移到右侧，Stage 卡片也随右侧有效主干移动。

### 4.3 active branch 与 active leaf

active branch 由问题节点的显式 `parentMomentID`、`isActiveBranch` 和分支状态共同决定。active leaf 的判定优先使用树结构：

1. 只考虑当前 Stage 的问题节点；
2. 排除旧分支、归档节点和不可见节点；
3. 计算问题节点在显式父子关系中的拓扑深度；
4. 选择没有活动子节点的叶节点；
5. 只有旧项目缺少父子关系时，才使用稳定生成顺序作为兼容回退。

因此，Stage 卡片、下一 Stage 的起点和问题资源卡都不会因为一个历史节点的时间戳而错误定位。

### 4.4 二叉回溯

回溯节点是结构上的分叉节点，而不是普通日志标签：

```text
公共主干
    ↓
回溯节点
  ↙     ↘
旧分支   新分支
灰色虚线  主色实线
```

旧分支保留为过程证据，但不再参与当前主线推进，也不展示资源卡。新分支继承回溯后的上下文，后续问题和资源继续绑定到新分支的问题节点。

## 5. 资源卡交互规范

### 5.1 收纳状态

- 资源卡的真实数据仍保存在所属问题节点的绑定关系中；
- 卡片以局部坐标叠放在问题节点后方；
- 默认最多显示三层错位边缘；
- 问题节点右下角显示绑定卡片数量；
- 不生成 `Evidence`、`Method` 等独立树节点；
- 不生成资源卡独立纵列或跨画布长连接线。

### 5.2 横向展开

展开时，卡片遵循确定性局部布局：

```text
卡片中心 X
= 问题节点中心 X
  + 问题节点半宽
  + 首卡间距
  + 卡片半宽
  + 卡片序号 ×（卡片宽度 + 卡片间距）
```

卡片中心 Y 始终与所属问题节点中心 Y 一致。卡片只扩展画布的展示边界，不改变问题树的结构坐标。

### 5.3 卡片类型与详情

不同资源类型使用独立的颜色、图标和图例：

- 论文（Paper）
- 方法（Method）
- 案例（Case Study）
- 设计原则（Design Principle）
- 课程框架（Course Framework）

点击已展开的资源卡会打开详情页，详情页显示：

- 资源卡类型与标题；
- 绑定的问题原文概括；
- 设计依据；
- 核心观点；
- 与当前 Stage 的关系；
- 原有卡片批注和引用信息。

### 5.4 手势优先级

- 明显横向拖动：控制所属问题的资源卡组；
- 明显纵向拖动：继续控制思维树画布平移；
- 轻触问题节点：打开问题详情；
- 左右拖动状态按问题节点独立保存，不会用一个全局展开状态覆盖其他问题。

## 6. 对话、Brief 与思维树同步

每次 AI 生成正式澄清问题时，系统同时保存：

- 完整问题文本：用于工作台和详情页；
- 概括问题文本：用于思维树节点；
- 当前 Stage；
- 当前 active branch 的父问题；
- 本轮调用的资源卡绑定；
- 回答、决策、修订和学习轨迹。

资源卡调用不会创建新的树节点，而是写入问题节点的资源绑定。方法调用记录和审计信息仍然保留在 SwiftData 中，用于详情、报告和 `.codesign` 导出。

未来阶段候选字段使用“延迟确认”策略：

```text
当前阶段发现未来字段
→ 保存候选值、证据与审计决定
→ 不写入未来 Brief 字段
→ 到达目标 Stage 后生成确认问题
→ 用户确认后提交字段并更新阶段进度
```

这样可以避免思维树和阶段进度因为一次偶然提及而提前跳转。

## 7. 批注、持久化与项目迁移

### 7.1 批注

v1.1.0 继续支持：

- 问题节点文字批注；
- 资源卡文字批注；
- Apple Pencil / PencilKit 手写笔迹；
- 批注拖动后的语义锚点重新绑定；
- Stage 收起时批注隐藏、展开时恢复；
- 资源卡收起时批注随卡片隐藏、展开时恢复。

资源卡批注锚定的是“问题资源绑定”语义，而不是一个临时 UI 节点。卡片展开或拖动时，批注位置根据局部卡片坐标重新投影。

### 7.2 SwiftData

SwiftData 继续保存真实项目数据：

- Project 与 Stage；
- ThinkingMoment 问题、回答、决策、回溯与分支关系；
- `parentMomentID`、`isActiveBranch`、`branchVersion`、`archivedAt`；
- 资源卡调用与问题绑定；
- 节点和卡片批注；
- Extraction audit log 与延迟确认记录；
- 学习轨迹和报告所需的过程证据。

思维树的节点位置属于可重算的展示投影，不作为旧项目坐标的唯一真值。

### 7.3 `.codesign` 兼容

导入旧项目时：

- 保留旧节点、旧分支、资源绑定和批注；
- 根据当前父子关系重新计算 active branch 和 active leaf；
- 对已完成 Stage 重新计算封口卡片位置；
- 对进行中的 Stage 隐藏历史上预生成的 Stage 卡片；
- 对资源卡只恢复所属问题的绑定，不重建资源独立节点；
- 对旧版本缺失的父子关系使用稳定顺序回退；
- 导入为新项目，不覆盖当前项目。

## 8. 其他体验调整

v1.1.0 同时收敛了近期使用中暴露的交互问题：

- 思维树使用点状网格背景，强化空间定位感；
- 点状网格的点径、间距和位移相位随画布缩放同步变化，放大缩小时保持空间比例；
- 展开节点时减少不必要的全树布局工作，改善明显延迟；
- 成果看板的连接线默认保持可见；
- 成果看板中未完成节点使用灰色低强调样式；
- 工作台底部阶段气泡的左右留白、图标和行间距重新整理；
- 阶段气泡支持点击空白区域关闭；
- 移除“生成边界草稿”入口及其不再使用的前置交互路径；
- 阶段问题中的资源卡不再以全局列形式出现。

## 11. 已知限制与后续方向

v1.1.0 已覆盖模拟器中的交互和数据回归，但以下内容仍适合在真实 iPad 上做一次人工体验验收：

- Apple Pencil 在不同压力和书写速度下的手感；
- 大量资源卡同时展开时的可读性；
- 超长问题文本与辅助功能字号下的卡片换行；
- 极深回溯树在小屏设备上的导航效率。

后续版本可以继续关注：

- 更明确的 Stage 完成确认反馈；
- 回溯节点的时间线筛选；
- 资源卡批量管理和搜索；
- 面向课堂协作的只读分享和批注合并；
- 更细粒度的思维树性能监控。
