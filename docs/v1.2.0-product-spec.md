# CoDesign Agent v1.2.0 产品说明

> **让 AI 不替用户完成设计，而是让每一次追问、判断、依据和修改都能被看见、批注与继续。**

**产品名称**：CoDesign Agent  
**版本**：v1.2.0  
**发布日期**：2026-08-02  
**版本主题**：有依据的苏格拉底式追问、开放式思维树、iPad 原生批注与完整设计状态共享  
**适用平台**：iPadOS / iOS / macOS（Designed for iPad）  
**核心用户**：设计类学生、创新项目团队、课程指导教师与智能产品初学者

---

## 1. 版本定位

CoDesign Agent 是一款面向开放式设计项目的 AI 设计澄清工作台。用户可以从一句尚未成形的想法开始，在 AI 的连续追问中逐步明确目标用户、核心场景、真实痛点、差异化价值、MVP 边界、技术方案、运行规则、验收指标、风险预案与项目排期。

它不是一键生成方案的写作工具，也不是要求用户依次填完字段的固定表单。v1.2.0 将产品能力集中到四个相互连接的核心创新：

1. **苏格拉底式隐式三段提问与资源卡依据**：每轮对话都包含设计线索、一个关键问题和可追溯的方法依据，但默认使用自然导师式表达，不展示机械模板。
2. **思维树可视化开放式设计流程**：把问题、回答、设计判断、阶段封口、回溯分支和资源依据放进同一棵可交互的推理树。
3. **Apple Pencil 思维树画布批注**：Apple Pencil 负责书写，手指继续负责移动和缩放画布，形成适合 iPad 课堂、工作坊和移动评图的原生体验。
4. **`.codesign` 整体状态导入导出**：保存并恢复项目结构、思维路径、资源、学习轨迹和批注，使设计现场能够被迁移、分享和继续。

v1.2.0 所交付的不只是一份 Design Brief，而是一套可解释、可回溯、可批注、可迁移的设计过程。

---

## 2. 产品解决的问题

开放式设计项目早期的困难通常不是缺少答案，而是缺少一条能够逐步形成判断的路径：

- 创意描述过于宽泛，无法对应具体用户、任务和情境；
- AI 过早生成完整方案，用户跳过问题定义、取舍与验证过程；
- 方法论与资料被罗列出来，却无法解释某个问题为什么值得问；
- 对话、草图、评语和设计决策散落在不同工具中；
- 修改前序结论后，旧方案和受影响的后续判断容易丢失；
- 课程提交只展示最终结果，无法证明设计思考真正发生过；
- 项目换设备或交给其他成员时，完整上下文难以延续。

CoDesign Agent 将 AI 对话、结构化抽取、设计依据、过程可视化、Apple Pencil 批注和项目状态归档组合为一个连续工作流，使“如何得到结论”与“结论是什么”具有同等价值。

## 3. 四项核心创新

### 3.1 苏格拉底式隐式三段提问与资源卡依据

传统 AI 助手常用长篇建议或选项列表替用户完成判断。CoDesign Agent 的目标相反：每轮只推进一个足以改变设计决策的问题，并在内部遵循三段式组织逻辑。

| 内部结构 | 作用 | 用户侧呈现 |
|---|---|---|
| 线索（Clue） | 指出当前方案中最值得注意的缺口、矛盾或隐含假设 | 一段简短、自然的导师式提示 |
| 提问（Question） | 聚焦一个能够改变 Design Brief 字段或设计判断的开放问题 | 独立、明确、可以直接回答的问题 |
| 依据（Basis） | 从本地方法卡、论文卡、案例卡、设计原则或课程框架中提供提问依据 | 收纳在对应问题节点上的资源卡，可按需展开查看 |

“隐式三段”并不等于输出三个标题。默认对话通常只呈现两个短段落：第一段内化线索或当前判断，第二段提出一个开放问题；方法依据由资源卡承担。这样既减少模板感和阅读负担，又保留“为什么这样问”的可解释性。

系统在提问前执行问题资格审查：用户回答之后，必须能够推动目标用户、核心场景、功能范围、技术路径、交互流程、边界取舍、评价标准、Stage 状态、思维树节点或学习轨迹发生有效变化。系统避免重复提问、无效情绪深挖以及不能影响设计决定的问题。

当用户表示“不确定”或“卡住”时，系统进入脚手架模式：先给一条帮助理解问题的线索，再提出一个开放问题；除非用户明确要求，不直接给 A/B/C 选项或替用户作答。资源推荐服务会结合当前 Stage、缺失字段、最近回答和问题类型筛选本地资源，再将最相关的 1–2 张卡片内化为本轮依据。

资源卡不是附属资料列表，而是问题的证据层。每张卡片记录类型、核心观点、适用原因、使用方式、关联 Stage 与引用信息，并绑定到它实际支撑的问题节点。用户可以直接查看“这个问题依据了什么”，而不是在全局资源库里反向寻找关系。

### 3.2 思维树可视化开放式设计流程

CoDesign Agent 将线性聊天记录转化为一棵能够生长、分叉、回溯和封口的设计推理树。思维树可以展示：

- 项目的初始模糊想法；
- 每个阶段的关键问题、回答和设计判断；
- 当前仍然有效的设计主线；
- 回溯后保留下来的旧方案分支；
- 已确认的 Design Brief 字段；
- 与具体问题绑定的方法和证据资源卡；
- 学习动作、手写笔迹和文本批注。

九个设计 Stage 提供专业骨架，但不是不可逆的线性向导。进行中的 Stage 保持开放生长，不提前出现封口卡片；只有阶段真正完成后，系统才在当前有效叶节点上方生成阶段封口。用户回到旧问题修改答案时，思维树形成左侧历史分支和右侧当前分支，旧方案不会被简单覆盖。

这种表达让用户能够同时回答三个问题：

```text
当前方案是什么？
它为什么变成现在这样？
过程中还出现过哪些可能性？
```

用户可以拖动画布、缩放、双击节点查看详情、长按可编辑节点，并直接操作问题节点后的资源卡组。资源卡展开时位于所属问题同一水平线上；收纳时以错位边缘和数量提示保留关系，不生成脱离问题的独立资源纵列。

思维树因此不是最终结果的装饰图，而是开放式设计流程的主交互界面。它允许方案在讨论、试错和回溯中继续发展，也让教师或团队成员能够观察问题定义、范围收敛和风险判断是否真正发生。

### 3.3 Apple Pencil 思维树画布批注

v1.2.0 使用 PencilKit 提供思维树手写批注，并支持系统级 Apple Pencil 输入策略。在“仅 Apple Pencil 书写”模式下：

- Apple Pencil 用于书写、圈画、标记和补充连线；
- 单指拖动继续平移思维树画布；
- 双指捏合继续缩放画布；
- 系统绘图工具可切换笔型、颜色和粗细；
- 支持撤销、重做和清空；
- 笔迹与文本批注随项目持久化。

这解决了批注层常见的输入冲突：手指松开在卡片或节点上时，不应被误判为书写；Apple Pencil 落笔时，手指仍应可以导航画布。产品由此更接近真实的移动评图、课堂讨论和设计工作坊，而不是把桌面交互简单缩小到触屏设备。

批注保存的不只是绝对屏幕坐标。节点、资源卡和 Stage 发生展开、收起或重新布局时，系统会根据语义锚点重新投影批注。资源卡收纳过程中，批注保持在其最终相对位置，不跟随卡片逐帧移动；卡片进入时批注渐隐，重新展开时再渐显，以降低布局更新和绘制带来的性能压力。

Apple Pencil 支持是 CoDesign Agent **提升 iPad 端移动应用竞争力**的重要能力：它把 AI 对话、可视化推理与自然手写整合到同一个工作现场，使 iPad 不只是内容查看终端，而是可以直接参与设计判断的创作设备。

### 3.4 `.codesign` 整体状态导入导出与思维共享

PDF 和 Markdown 适合阅读、提交与继续编辑，但它们只能保存静态结果。`.codesign` 是 CoDesign Agent 的交互项目包，用于保存可以重新打开的完整设计现场。

项目包包含：

- 项目基础信息、当前阶段和九阶段状态；
- 完整结构化 Design Brief；
- 思维树节点、父子关系和边；
- 当前有效分支、历史分支与方案版本；
- 决策路径、资源卡依据和学习轨迹；
- Apple Pencil 笔迹、文本批注及语义锚点；
- 画布状态、阶段展开状态和兼容迁移信息。

用户可以从项目中导出 `.codesign`，通过文件、云盘或协作工具交给其他成员。接收者可先只读预览，再导入为一个新项目。导入过程会重新建立阶段、Brief、思维节点、父子关系和批注锚点，使接收者能够从原有上下文继续澄清与修改，而不是只拿到一张截图或一份结论报告。

```text
保存设计现场
→ 分享项目包
→ 预览项目结构
→ 导入为新项目
→ 重建设计上下文
→ 继续提问、批注和迭代
```

`.codesign` 支持的是文件式、异步的设计协作和思维共享。它目前不等同于实时多人共同编辑，但已经能够让项目成员在交换文件时同时交换方案状态、判断依据和设计过程，减少协作中的上下文丢失。

## 4. 核心用户流程

```text
创建项目并输入模糊想法
→ 系统定位当前最值得推进的设计变量
→ 内化资源依据，给出一条线索和一个关键问题
→ 用户回答、请求换角度、查看例子或回溯旧问题
→ Design Brief、Stage、学习轨迹和思维树同步更新
→ 展开问题节点上的资源卡，检查提问依据
→ 使用 Apple Pencil 圈画、连线和添加批注
→ 完成阶段并生成阶段封口卡片
→ 导出中文 PDF / Markdown / JSON 或 .codesign 项目包
→ 分享、导入并继续设计
```

CoDesign Agent 使用九个阶段组织专业覆盖范围：

| 阶段 | 名称 | 关键产出 |
|---|---|---|
| 1 | 痛点与场景锚定 | 目标用户、核心痛点、使用场景 |
| 2 | 差异化价值提炼 | 核心价值、差异化 |
| 3 | 项目边界划定 | 做什么、不做什么 |
| 4 | 功能与技术方案拆解 | MVP 功能、技术模块、交互流程 |
| 5 | 运行逻辑与规则定义 | 运行逻辑、异常与规则 |
| 6 | 硬性约束设计 | 时间、预算、设备与技术约束 |
| 7 | 量化验收标准制定 | 指标、目标值与测量方式 |
| 8 | 风险识别与预案制定 | 风险、影响、触发条件与缓解策略 |
| 9 | 项目阶段拆分与排期 | 里程碑与阶段计划 |

## 5. 对话、Brief、Stage 与思维树同步

一次有效回答会同时作用于多个产品层：

1. 对话层记录完整问题、回答和上下文；
2. 结构化抽取层更新 Design Brief 候选字段；
3. 用户校准层允许确认、编辑或标记字段不准确；
4. Stage 层根据已确认字段更新完成度；
5. 思维树层生成问题、判断、回溯和资源绑定；
6. 学习轨迹层记录用户完成的设计思维动作；
7. 导出层将当前确认结果和完整过程分别映射到合适格式。

如果当前回答提前提到未来阶段的信息，系统会先保存为待确认候选，不会强行跳过中间阶段。进入目标 Stage 后，系统重新提出确认问题，用户确认后才写入对应字段并影响阶段完成度。

## 6. v1.2.0 关键交互改进

### 6.1 资源卡直接操作

- 问题节点向右拖动，用于展开其资源卡组；
- 展开后可直接把任意资源卡向左拖回问题节点完成收纳；
- 收纳手势采用更小的启动距离和方向性阈值，减少拖到边缘时的来回抽搐；
- 卡片始终使用所属问题的局部坐标，不反向改变思维树结构布局；
- 问题详情默认使用双击打开，减少画布平移结束时的误触。

### 6.2 批注显隐与性能

- 资源卡批注使用最终展开位置作为稳定锚点；
- 卡片拖动过程中不再让批注逐帧跟随；
- 收纳时批注渐隐，展开接近完成时渐显；
- Stage 收起时隐藏其批注，重新展开后按语义锚点恢复；
- Apple Pencil 输入变化采用延迟保存，减少连续书写时的数据写入压力。

### 6.3 首页与移动入口

- 首页在常用 iPad 横屏尺寸下保持单页展示，不依赖上下滚动；
- 首页聚焦开始新项目、继续最近项目、搜索、导入与设置；
- 最近项目固定展示三项，完整管理进入项目库；
- 顶栏、Hero 和最近项目采用独立交互层，装饰背景不拦截按钮触控；
- 首页品牌图标、透明设计树和背景视觉统一为 CoDesign 自有表达。

## 7. 输出与交接

不同格式承担不同职责：

| 格式 | 主要用途 | 内容重点 |
|---|---|---|
| PDF | 提交、评审、归档和对外展示 | 中文 AI 产品设计交接简报，只呈现已确认方案 |
| Markdown | 二次编辑与协作文档 | 可复制的结构化报告 |
| JSON | 调试、备份与数据迁移 | 机器可读的项目快照 |
| `.codesign` | 恢复工作现场、异步协作与思维共享 | 思维树、分支、资源、学习轨迹、批注和项目状态 |

PDF 使用独立的内容组织、语义映射、分页与绘制流程，将目标用户、产品范围、核心体验流程、AI 行为边界、验证指标和风险预案整理为紧凑的中文交接文档。完整过程证据不会被强行塞进对外 PDF；需要保存问题链、历史分支、资源与批注时，应使用 `.codesign`。

## 8. 数据、兼容与隐私边界

- 项目、Stage、Brief、思维节点、资源调用、学习轨迹与批注使用 SwiftData 本地持久化；
- 默认 Mock 模式无需 API Key，适合课堂演示、离线体验与测试；
- Live 模式支持 OpenAI-compatible Chat Completions 接口；
- `.codesign` 当前支持 `1.0`、`1.1`、`1.2` schema；
- 导入项目使用“导入为新项目”，不会覆盖本机原项目；
- 导入时重新映射节点标识和批注语义锚点，避免跨项目标识冲突；
- `.codesign` 是包含完整项目上下文的数据文件，分享前应确认其中是否存在不适合外传的内容。

## 9. 典型应用场景

### 课程开题与过程性评价

学生从一句模糊想法开始，在连续追问中形成问题定义和方案边界。教师不仅能查看最终 Brief，也能通过思维树观察取舍、回溯和方法依据。

### iPad 课堂评图

教师或同学在思维树上使用 Apple Pencil 圈出逻辑断点、风险节点和待验证假设；手指仍可移动、缩放画布，批注随项目保存。

### 创新工作坊与团队讨论

团队共同查看思维树，围绕具体问题节点展开资源依据，在旧分支和当前主线之间比较方案，讨论后继续更新 Brief。

### 异步协作与跨设备继续

项目负责人导出 `.codesign` 文件，其他成员预览并导入为新项目，恢复设计结构、批注和上下文，再继续澄清与迭代。

### 项目交接与作品集复盘

用户同时导出对外 PDF 和 `.codesign` 项目包：前者呈现已确认结果，后者保留完整设计过程，分别服务评审与后续继续工作。

## 10. 功能验收标准

### 苏格拉底式追问与依据

- [x] 默认每轮只提出一个能够推进设计判断的问题

- [x] 用户卡住时先提供线索，再提出开放问题
- [x] 本地资源按 Stage、缺失字段和问题类型推荐
- [x] 资源卡绑定到实际使用它的问题节点
- [x] 用户可以查看资源类型、核心观点、适用原因和引用信息

### 思维树与资源卡

- [x] 进行中的 Stage 保持开放生长
- [x] Stage 完成后才生成封口卡片
- [x] 回溯后保留历史分支和当前分支
- [x] 问题详情使用双击打开，降低画布误触
- [x] 问题节点右拖展开资源卡
- [x] 资源卡可直接左拖回问题节点收纳
- [x] 收纳和展开不会修改问题树结构坐标

### Apple Pencil 与批注

- [x] 支持 PencilKit 手写笔迹和系统绘图工具
- [x] 支持仅 Apple Pencil 书写策略
- [x] Apple Pencil 书写时单指仍可平移画布
- [x] Apple Pencil 书写时双指仍可缩放画布
- [x] 支持撤销、重做和清空

- [x] `.codesign` 保存 Stage、Brief、树结构和分支状态

## 11. 已知限制与后续方向

- `.codesign` 当前提供文件式异步协作，不支持实时多人同时编辑与冲突合并；
- Apple Pencil 压感、掌托和长时间书写体验仍应在不同型号真机上持续验收；
- 极深回溯树和大量资源卡同时展开时，仍需继续关注导航效率与性能；
- 本地资源卡目前以随应用发布的知识库为主，后续可增加团队自定义资源库；
- 批注合并、教师只读评阅模式和项目版本差异比较仍是后续协作方向。

**v1.2.0 用有依据的隐式追问推动设计，用开放思维树保存推理，用 Apple Pencil 留下人的判断，再用 `.codesign` 把完整设计现场交给下一位参与者。**
