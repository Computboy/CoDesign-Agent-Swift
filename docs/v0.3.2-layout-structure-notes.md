# CoDesign Agent v0.3.2 布局结构修复说明

**发布日期**: 2026-06-01  
**版本定位**: v0.3 工作台体验的结构性布局修复，不做颜色、阴影、圆角等视觉微调。

---

## 01. 修复目标

v0.3.2 聚焦 Project Detail 的澄清工作台布局稳定性，目标是解决宽屏三栏工作台中的结构问题：

- wide layout 中三栏各自独立滚动，导致页面出现多条明显滚动条；
- 中间顶部的 `AIContextNotice` 英文 Undo 提示卡缺少真实业务意义，干扰当前澄清卡片层级；
- `CurrentClarificationCard` 中 AI 回复文本没有撑满可用宽度，右侧出现异常留白；
- 流式输出时回复内容逐行增长，带动整张中间卡片不断变高；
- `AnswerComposer` 的发送按钮被 SwiftUI 默认 Button 背景包裹，出现灰色圆角框与内部圆形按钮重叠；
- `ProcessLogDisclosure` 在 wide layout 外层和 `CurrentWorkspaceColumn` 内部重复出现，容易造成底部异常空白或重复区域。

本版本只修改结构性布局，不调整视觉 token、色彩、阴影、圆角和卡片样式。

## 03. 当前工程结构

Project Detail 区域承担项目澄清流程的主要体验，结构如下：

```text
ProjectDetailView
└── ClarificationWorkspaceView
    ├── narrowLayout
    │   └── ScrollView
    │       └── VStack
    │           ├── WorkspaceHeader
    │           ├── StageRail
    │           ├── CurrentWorkspaceColumn
    │           └── InsightCardsPanel
    │
    └── wideLayout
        └── GeometryReader
            └── ScrollView
                └── HStack
                    ├── StageRailPanel
                    ├── CurrentWorkspaceColumn
                    └── InsightCardsPanel
```

`CurrentWorkspaceColumn` 是中间主工作列，负责组织当前澄清任务：

```text
CurrentWorkspaceColumn
├── WorkspaceHeader                # wide layout 中显示
├── DesignCompletionReviewCard     # 项目完成态
└── 未完成态
    ├── CurrentClarificationCard   # 当前 AI 澄清问题与快捷操作
    ├── AnswerComposer             # 用户输入区
    ├── LearningTraceSection       # 学习轨迹
    ├── Error Card                 # 可选错误提示
    └── ProcessLogDisclosure       # 过程记录，唯一保留位置
```

## 04. wide layout 滚动策略

### 修改前

wide layout 中左栏、中栏、右栏分别套了 `ScrollView`：

```text
HStack
├── ScrollView -> StageRailPanel
├── ScrollView -> CurrentWorkspaceColumn + ProcessLogDisclosure
└── ScrollView -> InsightCardsPanel
```

这种结构的问题是：

- 三栏各自成为滚动容器；
- 截图中容易出现三条独立滚动条；
- 三栏底部视觉不容易对齐；
- 中栏外层还有一份 `ProcessLogDisclosure`，和内部日志区重复。

### 修改后

wide layout 只保留一个页面级纵向滚动：

```text
GeometryReader
└── ScrollView(.vertical, showsIndicators: false)
    └── HStack(alignment: .top)
        ├── StageRailPanel
        ├── CurrentWorkspaceColumn
        └── InsightCardsPanel
```

策略说明：

- 三栏本身不再是独立滚动容器；
- 页面溢出时只由外层 `ScrollView` 统一滚动；
- 外层滚动条隐藏，避免工作台出现多条明显滚动条；
- `HStack` 设置最小高度，帮助三栏在宽屏工作台中保持稳定纵向承托；
- `ProcessLogDisclosure` 只保留在 `CurrentWorkspaceColumn` 内部。

## 05. AIContextNotice 处理

`AIContextNotice` 原本出现在中间主列顶部，内容为英文 Undo 提示。v0.3.2 没有删除组件文件，只从 `CurrentWorkspaceColumn` 的未完成态中移除调用。

修改后中间主列顶部直接进入：

```text
WorkspaceHeader
└── CurrentClarificationCard
```

这样当前 AI 澄清卡片成为明确的视觉和业务起点，不再被无业务意义的提示卡抢占层级。

## 06. CurrentClarificationCard 结构修复

### 文本宽度

`streamingContent` 和 `responseContent` 中的 AI 回复文本统一设置：

```swift
.frame(maxWidth: .infinity, alignment: .leading)
```

覆盖范围包括：

- `Text(attributed)`，即 Markdown 转换后的 `AttributedString` 文本；
- `Text(streamingText)`；
- `Text(latestAssistantText)`；
- 外层内容容器。

目的：

- 让 AI 回复文本占满中间卡片可用宽度；
- 避免回复文本只占左侧部分区域；
- 保持 Markdown 文本和普通文本宽度行为一致。

### 回复区域高度

新增固定高度常量：

```swift
private let responseAreaHeight: CGFloat = 190
```

`streamingContent` 和 `responseContent` 中的可滚动回复区域设置为：

```swift
.frame(
    maxWidth: .infinity,
    minHeight: responseAreaHeight,
    maxHeight: responseAreaHeight,
    alignment: .topLeading
)
```

设计意图：

- 回复区域高度稳定在 160-220 的建议范围内；
- 流式输出时中间卡片不会随着每一行文字持续增高；
- 内容超出后在回复区域内部滚动；
- 内部滚动条隐藏，避免出现明显滚动条。

注意：这里保留的是 AI 回复区域内部滚动，不是三栏独立滚动。它用于承载长文本内容，不承担页面布局滚动。

## 07. AnswerComposer 结构修复

### 发送按钮

发送按钮显式设置：

```swift
.buttonStyle(.plain)
```

目的：

- 移除 SwiftUI 默认 Button 背景；
- 避免外层灰色圆角方块与内部圆形发送按钮重叠；
- 保持发送按钮只显示自定义圆形背景。

### 输入区对齐

`AnswerComposer` 移除原本的水平内边距：

```swift
// before
.padding(.horizontal, AppTheme.Layout.cardPadding)

// after
.frame(maxWidth: .infinity)
```

目的：

- 让输入框和发送按钮的右边缘与上方 `CurrentClarificationCard` 卡片右边缘对齐；
- 避免输入区被额外缩进，造成上下结构不齐。

## 08. ProcessLogDisclosure 去重

修改前：

```text
ClarificationWorkspaceView.wideLayout
└── 中栏 ScrollView
    ├── CurrentWorkspaceColumn
    │   └── ProcessLogDisclosure
    └── ProcessLogDisclosure
```

修改后：

```text
CurrentWorkspaceColumn
└── ProcessLogDisclosure
```

保留原则：

- 过程记录属于中间主工作列的一部分；
- wide layout 不再在外层额外追加日志区；
- narrow layout 与 wide layout 共享 `CurrentWorkspaceColumn` 的日志位置，减少分支行为差异。

v0.3.2 的验收点：

- wide layout 截图中不再看到三栏各自明显滚动条；
- 中间顶部不再出现英文 Undo 提示卡；
- AI 回复文字占满中间卡片宽度，右侧不再空出一块；
- 流式输出时回复区域高度稳定，卡片不会随文字逐行持续撑高；
- 发送按钮没有灰色重叠圆角框；
- `ProcessLogDisclosure` 只出现一次；
- 三栏底部视觉尽量对齐，不出现左栏无限延伸、中栏提前结束的异常观感。

## 11. 后续建议

v0.3.2 已把工作台布局问题收敛到结构层。后续如果继续优化，应优先做交互或信息架构层面的改动，例如：

- 明确 `ProcessLogDisclosure` 是否默认折叠；
- 给长回复区域增加“展开查看全部”能力；
- 将 `AIContextNotice.swift` 标记为废弃或在后续版本中删除；
- 为 wide layout 增加截图级 UI 回归检查。
