# CoDesign Agent v0.5.2 说明文档

**日期**: 2026-06-10  
**版本定位**: 轻量本地设计论文 RAG + 隐式三段流追问 + 工作台排版稳定性修复 + 首页视觉重绘  
**范围约束**: 不新增后端，不把联网论文搜索作为主流程，不改变 SwiftData 核心模型，不把产品改回普通 Chatbot

---

## 01. 版本目标

v0.5.2 是一次围绕“资源卡如何成为 AI 的设计依据，而不是用户的阅读负担”的精修版本。

本次改进聚焦三件事：

1. 将现有 ResourceCard / ResourceLibrary / ResourceRecommendationService 升级为轻量本地设计知识库，也就是 Lightweight Design Paper RAG。
2. 将 AI 主回答从显式模板化的“线索 / 追问 / 依据”改为自然导师式表达，但内部仍保留“线索 + 提问 + 依据”的组织逻辑。
3. 修复工作台中 AI 输出框、思维树根节点、回溯提示、追问意图卡片等视觉细节问题，让界面更稳定、更少空白、更少截断。
4. 将首页从普通项目列表升级为带树图视觉、行动入口、搜索与最近项目区的产品化首页。

核心原则：

```text
资源卡主要服务 AI，不默认塞进用户主回答。
AI 可以有依据，但不要每轮像论文阅读器。
追问可以有结构，但用户看到的是自然的设计导师表达。
UI 不应该用固定高度和省略号掩盖内容。
```

## 02. 轻量本地设计论文 RAG

### 2.1 ResourceCard 数据结构增强

核心文件：

```text
CoDesign-Agent/Models/ResourceCard.swift
```

新增了面向“论文观点卡 / 研究洞察卡”的可选字段：

```swift
authors: String?
citation: String?
researchInsight: String?
designImplication: String?
ragUse: String?
evidenceNote: String?
confidenceHint: String?
```

这些字段全部有默认值 `nil`，不破坏既有初始化方式。

同时新增和强化了 computed fallback：

- `promptResearchInsight`
- `promptDesignImplication`
- `promptRAGUse`
- `evidenceDisplayText`
- `confidenceDisplayText`
- `compactPublicationText`
- `sourceDisplayText`
- `promptCoreIdea`
- `promptAgentUse`
- `userDisplayText`

这样旧卡片仍然可以正常工作，新论文卡也能给 prompt 和 UI 提供更清晰的表达。

### 2.2 新增 paperCards

核心文件：

```text
CoDesign-Agent/Services/ResourceLibrary.swift
```

`ResourceLibrary.all` 已改为：

```swift
paperCards + methodCards + theoryCards + legacyCards
```

新增 14 张轻量论文 / 理论观点卡。它们不是论文全文，而是 distilled card，用于帮助 AI 检索和生成追问。

新增卡片如下：

| Card ID | 主题 | 主要服务场景 |
|---|---|---|
| `paper-wicked-problem-framing` | Wicked Problem / Problem Framing | 主题过大、问题不清、边界不稳 |
| `paper-reflective-practice` | Reflective Practice | 用户卡住、不确定、缺少判断依据 |
| `paper-designerly-ways` | Designerly Ways of Knowing | 用户先讲功能或方案，需要反推问题假设 |
| `paper-design-thinking-wicked` | Design Thinking as Framing | 避免把设计流程变成机械填表 |
| `paper-research-through-design` | Research through Design | 原型、评价、里程碑如何连接关键假设 |
| `paper-hai-guidelines` | Human-AI Interaction Guidelines | AI 产品的透明度、控制、失败恢复 |
| `paper-mixed-initiative` | Mixed-Initiative Interaction | 人机主动权、确认机制、系统何时建议 |
| `paper-human-centered-ai-control` | Human-Centered AI Control | Human-in-the-loop、自动化边界、责任边界 |
| `paper-ai-explainability` | Explainability | AI 解释如何帮助用户理解和纠错 |
| `paper-uncertainty-communication` | Uncertainty Communication | 置信度、不确定性、风险提示 |
| `paper-automation-bias` | Automation Bias | 防止过度信任 AI 或自动化建议 |
| `paper-cognitive-load-scaffolding` | Cognitive Load / Scaffolding | 用户不知道怎么答时降低认知负荷 |
| `paper-scaffolding-learning` | Scaffolding by Questioning | 给线索但不替用户回答 |
| `paper-goodhart-success-metrics` | Goodhart / Success Metrics | 成功指标与真实用户改善的关系 |

没有伪造 DOI 或页码。`citation` 仅采用简洁形式，例如 `Amershi et al., 2019, CHI`。

### 2.3 推荐逻辑升级

核心文件：

```text
CoDesign-Agent/Services/ResourceRecommendationService.swift
```

资源推荐不再只是“按分数取前几张”，而是转成轻量 RAG 的多样化选择。

仍然保留的基础信号：

- 当前阶段 `relatedStages`
- 缺失字段 `missingFields`
- 问题类型 `problemTypes`
- tags / keywords
- `StageDefinition.recommendedCardIDs`

新增或强化的逻辑：

- `.paper` 类型获得合理权重，但不会永远压过 method。
- 正常模式优先组合：
  - 1 张内容 / 方法卡；
  - 1 张论文观点卡；
  - 1 张提问或脚手架策略卡。
- `stuckScaffold` 模式优先选择能转译成“线索”的卡，而不是纯内容解释卡。
- 用户表达“不确定 / 不知道 / 卡住”时，提高 scaffoldingStrategy、questionStrategy、cognitiveDepth、paper insight 的权重。
- AI 项目提高 Human-AI、Transparency、HITL、Boundary、Failure 相关卡权重。
- Stage 7 评价标准阶段提高 Evaluation、Goodhart、Success Metrics 相关卡权重。
- Stage 3 边界阶段提高 Boundary、Scope、MVP、Human Control 相关卡权重。

## 03. 隐式三段流

### 3.1 Prompt 从硬模板改为自然表达

核心文件：

```text
CoDesign-Agent/Services/Prompts/SocraticPromptTemplates.swift
CoDesign-Agent/Services/Dialogue/DesignDialoguePlanner.swift
CoDesign-Agent/Services/Mock/MockLLMService.swift
```

旧策略容易诱导模型硬换行和机械标题：

```text
线索：
追问：
依据：
每行不超过 32 个中文字符
每次回复控制在 4-7 行
```

v0.5.2 改为：

- 不要手动硬换行，交给 SwiftUI 自然换行。
- 默认输出 2 个短段落：
  - 第一段：设计线索 / 当前判断；
  - 第二段：一个开放但具体的问题。
- 最后一段必须包含明确、可回答的问题。
- 默认不要输出 Markdown 表格、长列表、A/B/C 选项。
- 默认不要显式输出“线索：/追问：/依据：”。
- 可以自然表达为：“这里更关键的线索是……所以我想先确认……”

内部仍然保留三段流：

```text
clue / 线索：帮助用户理解当前缺口
question / 提问：只问一个能改变设计判断的问题
basis / 依据：来自本地 RAG 的 1-2 张卡
```

但外部呈现变为自然导师式表达。

---

### 3.2 RAG Prompt 上下文

Prompt 中“当前资源卡”改为：

```text
本地 RAG 检索结果（内部使用）
```

每张卡以紧凑结构提供给 LLM：

```text
cardID
type / role
title
triggerProblem
coreIdea / researchInsight
designImplication / agentUse
suggestedQuestion
expectedFields
basisLabel
```

明确约束：

- 这些卡片是内部依据，不要逐条讲给用户。
- 选择 1-2 张最相关卡，内化为设计线索。
- 不要把论文名、作者名、卡片标题生硬塞进主回答。
- 只有用户追问“为什么这样问 / 依据是什么”时才展开依据。
- 默认由 UI 用标签或抽屉展示依据。

### 3.3 卡住模式与快捷按钮

核心文件：

```text
CoDesign-Agent/Views/ProjectDetail/CurrentClarificationCard.swift
```

“我还不确定”快捷按钮从硬模板提示改为自然提示：

```text
我还不确定。请先给我一条能帮助理解当前问题的设计线索，再只问一个开放问题。不要给选项，不要替我回答。
```

`usesMethodScaffold` 不再只依赖 `latestAssistantText.contains("线索：") && contains("追问：")`。

现在优先根据：

- 最近一次 `momType == "method"` 的 ThinkingMoment；
- 最近一次 `actionType == "methodCard"` 的 LearningTrace；
- 旧文本检测作为 fallback。

UI 文案改为：

```text
本轮使用本地设计依据辅助追问
```

---

### 3.4 问题提取增强

核心文件：

```text
CoDesign-Agent/ViewModels/ChatViewModel.swift
```

`questionMomentText(from:)` 不再依赖显式“追问：”。

新的提取策略：

1. 如果包含“追问：”，继续兼容旧格式。
2. 否则提取最后一个以中文问号或英文问号结尾的句子。
3. 如果有多个问题，优先取最后一个。
4. 如果没有问号，取最后一句。
5. 这样自然语言格式不会导致思维树的问题节点记录失败。

## 05. AI 输出排版修复

### 5.1 新增 AssistantResponseTextView

新增文件：

```text
CoDesign-Agent/Views/Components/AssistantResponseTextView.swift
```

用于统一 assistant 文本显示，覆盖：

- 已保存的 assistant message；
- streaming 中的 assistant response；
- 当前澄清卡片里的主回复。

内置 `AssistantTextNormalizer`，用于：

- 统一 CRLF 为 LF；
- 去掉开头结尾空白；
- 将 3 个以上连续换行压缩为 2 个；
- 去掉模型偶发输出的 Markdown 标题符号；
- 合并模型主动硬切开的中文短行；
- 保留基本 Markdown bold 渲染能力；
- 不破坏中文问号。

### 5.3 当前澄清卡回复区域自适应高度

用户反馈的问题：

```text
AI 说得少时下面空一大片。
AI 说得多时要在内部上下滚动才能看到全部。
```

原因：

```text
CurrentClarificationCard 里保留了固定 190pt 的 AssistantResponseViewport。
```

v0.5.2 修复：

- 移除固定高度回复视口。
- 移除内部 ScrollView。
- 改为 `AssistantResponseBlock`，让内容自然撑高。
- 短回复高度更小，长回复自然增高。

### 5.4 追问意图 / 可能更新卡片视觉对齐

用户反馈的问题：

```text
“追问意图”和“可能更新”两个卡片不一样高。
```

```text
两个卡片按各自内容自然高度撑开；右侧 chip 行高和 padding 更高。
```

### 5.7 首页重绘

本次新增独立首页视图：

```text
CoDesign-Agent/Views/ProjectList/CoDesignHomeView.swift
```

首页按粘贴稿方向实现为：

- 顶部自定义导航栏：品牌、设置、新建项目、搜索项目。
- 首屏 Hero：左侧叙事文案与行动按钮，右侧树图视觉。
- 右侧树图使用 asset 图片 `hero_design_tree`，周围浮动卡片用 SwiftUI 绘制。
- 下方展示三张能力卡：思维树生长、本地知识库依据、工作台沉淀。
- 最近项目区接入真实 SwiftData 项目，而不是静态示例数据。
- 项目卡可继续进入详情页，可通过上下文菜单删除。
- 搜索框复用 `ProjectListViewModel.filteredProjects(_:)`，搜索结果直接体现在首页项目区。
- 宽屏保持左右布局，窄屏自动改为上下布局；首页标题在窄屏下分行，避免文字被裁切。

图片资源已从项目根目录的 `tree.png` 复制到：

```text
CoDesign-Agent/Assets.xcassets/hero_design_tree.imageset/tree.png
```

`ProjectListView` 现在作为数据和 sheet 容器，负责把真实项目、创建项目、设置弹窗、删除项目等动作传入 `CoDesignHomeView`。

## 08. 保留与未做

本版本明确没有做：

- 没有新增后端；
- 没有新增登录；
- 没有新增实时多人协作；
- 没有把联网论文搜索作为主路径；
- 没有把完整论文摘要塞进用户主对话；
- 没有要求 AI 每轮显式输出“线索 / 追问 / 依据”；
- 没有修改 SwiftData 核心模型；
- 没有删除已有资源卡、思维树、工作台、Mock/Live 服务模式。

仍需注意：

- `MockLLMService.stageResponses` 中保留了 legacy 旧格式文本，作为历史兼容数据；当前运行时 mock chat 已改为自然表达。
- 根节点圆角矩形会随文字增高，极长项目名在思维树里会占用更多空间，这是为了满足“不省略文字”的显示要求。
