# CoDesign Agent v1.0 应用说明

**版本定位**: 面向设计类与创新类课程项目的 AI 设计澄清工作台  
**适用对象**: 设计学生、创新创业课程学生、课程指导教师、项目评审与演示者  
**核心目标**: 帮助用户从一个模糊想法出发，通过连续追问、结构化抽取、过程可视化和报告导出，形成一份可讨论、可迭代、可提交的 AI 产品设计简报。

---

## 1. 应用是什么

CoDesign Agent 不是普通聊天机器人，也不是一键生成开题报告的写作工具。它更像一位设计思维训练伙伴：用户先提出一个还不成熟的项目想法，系统不急着替用户给出最终方案，而是通过苏格拉底式追问，引导用户逐步澄清目标用户、核心痛点、使用场景、价值差异、项目边界、MVP 功能、技术方案、运行规则、约束、验收标准、风险和里程碑。

应用的核心体验可以概括为：

```text
模糊想法
→ AI 追问
→ 用户回答
→ 结构化 Design Brief 自动更新
→ 阶段进度与学习轨迹同步变化
→ 思维树和成果看板呈现过程
→ 导出报告或项目包
```

它强调“训练用户做设计判断”，而不是“替用户完成所有判断”。因此，系统会给出线索、提问和结构化反馈，但最终项目定义仍由用户确认、修正和推进。

---

## 2. 面向的使用场景

CoDesign Agent v1.0 主要服务以下场景：

1. 设计类课程开题  
   学生只有一个大致方向，例如“想做一个校园导航工具”，但还没有讲清楚用户是谁、场景是什么、要解决哪类具体问题。

2. 创新创业项目早期梳理  
   团队需要把创意收敛成 MVP 范围、价值主张、风险预案和阶段计划。

3. AI 产品设计训练  
   用户希望学习如何从问题、用户、场景、价值、边界、约束和指标等维度完整思考一个产品项目。

4. 课程过程记录与作品集沉淀  
   用户不仅需要最终报告，也需要展示自己经历了哪些设计判断、如何从模糊走向清晰。

5. 指导教师辅助评阅  
   教师可以通过导出的报告、Design Brief、思维树和学习轨迹，查看学生是否真正完成了问题澄清和方案收敛。

## 3. 核心功能总览

### 3.1 项目首页与项目库

打开应用后，用户进入 CoDesign 首页。首页承担“开始”和“回到最近项目”的职责：

- 新建一个设计澄清项目；
- 继续最近项目；
- 搜索已有项目；
- 查看最近 3 个项目；
- 进入完整项目库；
- 导入 `.codesign` 项目包；
- 打开 API 设置。

当项目较多时，完整管理进入“项目库”。项目库支持搜索项目名称和项目描述、打开项目、删除项目、新建项目、导入项目包和进入设置页。

### 3.2 新建项目

新建项目页的标题是“从一个模糊想法开始”。用户只需要填写一个最初的设计想法即可开始，其他信息均为可选。

可输入内容包括：

- 当前设计想法；
- 项目类型；
- 已知限制；
- 希望 AI 先帮忙澄清的优先方向。

系统会根据初始想法自动生成项目名称，并把项目类型、限制和澄清优先级合并进项目描述，作为后续 AI 追问和结构化抽取的上下文。

### 3.3 9 阶段设计澄清流程

CoDesign Agent 把设计澄清过程拆为 9 个阶段。每个阶段都有明确目标和对应的 Design Brief 字段。

| 阶段 | 名称 | 主要问题 | 关键产出 |
|---|---|---|---|
| 1 | 痛点与场景锚定 | 谁遇到了什么问题？问题发生在什么具体场景？ | 目标用户、核心痛点、使用场景 |
| 2 | 差异化价值提炼 | 为什么用户需要这个方案？它和现有方案有什么不同？ | 核心价值、差异化 |
| 3 | 项目边界划定 | MVP 第一版做什么、不做什么？ | 做的边界、不做的边界 |
| 4 | 功能与技术方案拆解 | 需要哪些功能、模块和交互流程？ | MVP 功能、技术模块、交互流程 |
| 5 | 运行逻辑与规则定义 | 系统如何运转？有哪些规则和异常处理？ | 运行逻辑 |
| 6 | 硬性约束设计 | 时间、预算、技术、设备等限制是什么？ | 硬性约束 |
| 7 | 量化验收标准制定 | 如何判断项目成功？指标如何测量？ | 验收指标、目标值、测量方式 |
| 8 | 风险识别与预案制定 | 项目最可能在哪里失败？如何提前应对？ | 风险项、影响程度、缓解策略 |
| 9 | 项目阶段拆分与排期 | 下一步如何落地？有哪些里程碑？ | 里程碑、阶段计划 |

阶段不是普通的页面导航，而是系统判断项目成熟度的骨架。用户的每次回答都会影响字段完整度，字段完整度会影响阶段状态和整体完成率。

### 3.4 主工作台

Project Detail 是应用的主要工作区。v1.0 的工作台根据屏幕尺寸自适应：

- 桌面宽屏和 iPad 横屏：思维树与当前澄清区域并排展示；
- iPad 竖屏和窄屏：阶段条、当前澄清卡片和辅助面板入口纵向排列；
- iPhone 窄屏：优先展示当前追问和回答输入，思维树、资源线索、Design Brief 通过面板打开。

工作台包含以下核心区域：

- 当前澄清卡片；
- 本轮设计依据；
- 追问意图；
- 可能更新的字段；
- 回答输入框；
- 快捷操作；
- 学习轨迹；
- 过程记录；
- Design Brief 折叠面板；
- 阶段条或嵌入式思维树。

### 3.5 苏格拉底式 AI 追问

AI 的任务不是直接给答案，而是根据当前阶段、已有 Design Brief、最近回答和资源线索，提出下一轮最值得推进的问题。

常见追问包括：

- “这个问题最典型地发生在什么时间、地点或任务情境中？”
- “如果只能做第一版，哪些功能必须保留，哪些应该排除？”
- “你的方案相比现有做法，真正新增的价值是什么？”
- “这个项目成功时，应当出现哪些可观察、可测量的结果？”

系统约束每轮尽量聚焦一个关键问题，避免一次性抛出过多填空项。

### 3.6 快捷操作

当用户不知道如何回答时，可以使用当前澄清卡片下方的快捷操作：

| 快捷操作 | 作用 |
|---|---|
| 我还不确定 | 触发“线索 + 追问”模式，系统先给一条思考线索，再问一个开放问题 |
| 换个角度问 | 要求 AI 用不同角度重新提问 |
| 生成边界草稿 | 基于已有回答草拟 MVP 范围，但不替用户最终决定 |
| 跳过 | 暂时跳过当前问题，继续推进到下一个合理澄清点 |
| 给我一个例子 | 在用户停留一段时间后出现，用短例子提供启发 |

快捷操作本质上也是用户输入。点击后，系统会把对应提示加入对话，再执行同样的抽取、分析和追问流程。

### 3.7 资源线索与本地设计依据

系统内置设计方法资源卡，例如 Persona、同理心地图、用户旅程图、5 Whys、How Might We、MVP、假设映射、预演失败、可用性测试等。

资源卡的作用是提供“思考脚手架”，不是替用户选择答案。系统会根据当前阶段、缺失字段、用户最近输入和是否卡住，推荐一组本轮相关的资源线索。普通模式最多使用 5 张资源卡，卡住时的线索模式会更聚焦，通常使用 2 张以内。

用户可以在资源线索面板查看：

- 本轮 AI 为什么这样问；
- 相关设计方法的简短说明；
- 这些方法可能帮助澄清的字段；
- 被系统记录下来的提问依据。

### 3.8 结构化 Design Brief

Design Brief 是项目最终沉淀的结构化成果。它不是用户手动填写出来的表单，而是系统从自由对话中持续抽取、校验和更新的结果。

v1.0 中主要字段包括：

- 目标用户；
- 核心痛点；
- 使用场景；
- 核心价值；
- 差异化；
- 项目边界；
- MVP 功能；
- 技术模块；
- 交互流程；
- 运行逻辑；
- 硬性约束；
- 验收标准；
- 风险预案；
- 里程碑。

用户可以对字段进行人工修正：

- 查看字段内容；
- 编辑字段；
- 确认字段正确；
- 标记字段不准确；
- 在字段卡片上进行快捷确认或标记。

这使 Design Brief 成为“AI 提取 + 用户校准”的协作产物，而不是完全由模型单方面决定。

### 3.9 阶段进度与完成度

系统会根据 Design Brief 字段是否填充来计算每个阶段的完成度。阶段状态会随对话自动变化：

- 未开始；
- 进行中；
- 需要回看或修正；
- 已完成。

整体完成率来自各阶段进度。完成率不仅用于展示进度，也会影响完成态卡片、成果看板成熟度和导出报告内容。

### 3.10 学习轨迹

学习轨迹记录用户完成的设计思维动作，例如：

- 锚定了痛点场景；
- 提炼了差异化价值；
- 收缩了项目范围；
- 明确了验收标准；
- 识别了关键风险；
- 使用了某个设计方法线索完成一次重新思考。

学习轨迹的价值在于帮助用户看见自己的思考过程。对于课程项目，它可以作为过程性学习证据，而不只是最终方案展示。

### 3.11 过程记录

过程记录保存对话和方法调用片段。用户可以回看：

- 自己曾经如何回答；
- AI 曾经如何追问；
- 某个字段可能来自哪轮对话；
- 哪些资源线索影响了本轮追问；
- 回溯后旧分支如何形成。

过程记录默认不抢占主视觉空间，在需要复盘时可以展开查看。

### 3.12 思维树

思维树把项目澄清过程可视化为一棵设计推理树。它展示：

- 项目初始想法；
- 9 个设计阶段；
- 每阶段产生的问题、回答、判断和字段；
- 已填充字段；
- 当前主线；
- 回溯后留下的旧分支。

用户可以缩放、拖动、点击节点查看详情，也可以在独立视图或工作台嵌入视图中查看。旧分支不会被简单丢弃，而是作为设计推理过程的一部分保留下来，帮助用户理解方案为什么发生变化。

### 3.13 成果看板

成果看板把结构化 Design Brief 转为更适合展示的视觉结果，包括：

- 项目成熟度；
- 字段澄清统计；
- 澄清地图；
- MVP 边界画布；
- 风险矩阵；
- 设计演进记录。

成果看板适合在项目中后期查看当前方案是否已经足够清晰，也适合用于课堂展示前的自检。

### 3.14 作品档案

作品档案用于沉淀更完整的课程过程材料，包括：

- 设计作品画布；
- Design Brief 海报；
- 设计旅程时间线；
- Thinking Action Cards；
- 证据墙；
- 学习反思总结。

它强调“过程和成果一起展示”，适合课程汇报、作品集整理和复盘。

### 3.15 对话、进度与洞察视图

除工作台外，项目详情中还提供多个视图：

| 视图 | 用途 |
|---|---|
| 工作台 | 默认主视图，用于回答当前追问和推进项目 |
| 思维树 | 查看设计推理结构、问题链和回溯分支 |
| 成果 | 查看可视化成果看板 |
| 作品档案 | 查看面向课程汇报和反思的过程档案 |
| 对话 | 以传统聊天方式查看完整对话 |
| 进度 | 查看 9 阶段完成情况 |
| 洞察 | 查看完整 Design Brief 和学习轨迹 |

日常推进建议优先使用“工作台”；复盘和展示时使用“思维树”“成果”和“作品档案”。

### 3.16 报告导出

v1.0 支持导出多种格式：

| 格式 | 适合用途 |
|---|---|
| PDF 报告 | 提交、评审、归档、对外展示 |
| Markdown 文档 | 后续编辑、同步到 Notion / 飞书 / GitHub / PRD |
| JSON 数据 | 备份、开发调试、未来数据迁移 |
| CoDesign 交互项目包 `.codesign` | 保存完整设计过程、思维树、回溯分支、Design Brief 与资源线索 |

导出时可以选择是否包含：

- 最终设计报告；
- 资源线索与引用；
- 对话摘要；
- 完整思维树快照；
- 回溯分支与旧方案。

`.codesign` 项目包可以重新导入应用，进入只读预览，查看思维树、路径、Brief、资源和摘要，也可以导入为新项目继续保存。

### 3.17 Mock 与 Live 模式

应用支持两种服务模式：

- Mock 模式：默认模式，不需要 API Key，适合离线演示、开发调试和课堂展示；
- Live 模式：调用真实 OpenAI-compatible API，适合真实 AI 对话和结构化抽取。

设置页支持配置：

- API Key；
- Base URL；
- Model；
- Thinking Type。

设置页还提供“测试 API Key”按钮。测试成功后，系统会自动切换到 Live 模式；如果用户仍处于 Mock 模式，聊天不会调用真实模型。

## 4. 输入与输出

### 4.1 用户输入

用户在应用中可能输入以下内容：

1. 新建项目输入  
   包括设计想法、项目类型、已知限制和澄清优先级。

2. 对话回答  
   用户对 AI 追问的自然语言回答，是系统最核心的数据来源。

3. 快捷操作  
   用户通过按钮表达“我还不确定”“换个角度问”“生成边界草稿”等意图。

4. 字段修正  
   用户手动编辑 Design Brief 字段，确认或标记字段不准确。

5. 配置信息  
   用户在设置页输入 API Key、Base URL、模型名和 Thinking Type。

6. 外部项目包  
   用户导入 `.codesign` 文件，预览或导入为新项目。

### 4.2 系统输出

系统会产生以下输出：

1. AI 追问  
   基于当前阶段和已有上下文生成下一轮澄清问题。

2. 设计线索  
   当用户卡住时，系统输出一条本地设计依据或思考方法，再提出一个开放问题。

3. Design Brief  
   从对话中抽取并更新结构化项目字段。

4. 阶段进度  
   自动更新每个阶段状态和完成度。

5. 学习轨迹  
   记录用户完成的关键设计思维动作。

6. 过程记录  
   保存对话、方法调用和问题链。

7. 思维树  
   将项目想法、阶段、问题、判断、字段和回溯分支可视化。

8. 成果看板与作品档案  
   将结构化内容转换为更适合展示和复盘的视觉材料。

9. 导出文件  
   生成 PDF、Markdown、JSON 或 `.codesign` 项目包。

10. 状态反馈  
   包括 API 测试成功或失败、导出完成或失败、项目包导入结果等。

## 5. 系统与用户的交互逻辑

### 5.1 一轮对话内部发生了什么

每次用户发送回答后，系统会执行以下逻辑：

1. 保存用户消息  
   用户输入被保存到当前项目的对话历史。

2. 判断澄清模式  
   系统根据用户输入判断是普通回答、卡住、请求示例、换角度、边界草稿还是跳过。

3. 读取当前项目快照  
   系统获取发送前的 Design Brief 状态，用于后续比较哪些字段发生了变化。

4. 结构化抽取  
   系统从完整对话中抽取结构化字段，并与已有字段合并。

5. 校验与更新 Brief  
   抽取结果会经过字段校验、置信处理和合并，再写入 Design Brief。

6. 更新阶段进度  
   进度分析器根据字段完整度重新计算 9 阶段状态。

7. 记录学习轨迹和思维节点  
   如果用户补全了重要字段或完成了关键设计动作，系统会记录学习轨迹和思维树节点。

8. 推荐资源卡  
   系统根据当前阶段、缺失字段和用户输入选择相关设计方法资源。

9. 生成下一轮 AI 追问  
   AI 基于更新后的 Brief、当前阶段和资源卡生成下一轮问题。

10. 保存 AI 回复  
   AI 回复被加入对话历史，并同步进入过程记录和思维树。

这个顺序很关键：系统不是先随便聊天再整理，而是先吸收用户刚刚给出的信息，更新结构化状态，再决定下一轮最需要问什么。

### 5.2 用户与系统的责任分工

| 参与者 | 主要职责 |
|---|---|
| 用户 | 提供真实想法、回答追问、修正字段、确认判断、决定最终方案 |
| AI | 提出聚焦问题、提供思考线索、帮助用户继续推进 |
| 结构化抽取层 | 从对话中提取 Design Brief 字段 |
| 进度分析层 | 判断阶段完成度和下一步推进方向 |
| 可视化层 | 展示思维树、成果看板、作品档案和学习轨迹 |

### 5.3 回溯与修正逻辑

设计澄清不是线性填表。用户可能在后续阶段发现前面判断不准确，例如目标用户过宽、MVP 范围过大、风险没有考虑清楚。

当用户修正字段或重新回答关键问题时：

- Design Brief 会更新；
- 阶段完成度可能变化；
- 思维树会保留旧分支；
- 新判断会成为当前主线；
- 旧方案不会简单消失，而是作为回溯证据存在。

这种机制让应用更接近真实设计过程：设计不是一次写对，而是在追问和修正中逐渐成形。

## 6. 从零开始使用的完整流程

### 6.1 第一次打开应用

用户打开应用后进入 CoDesign 首页。若是首次使用，首页会展示创建项目入口。用户可以直接点击“新建项目”或“开始新的澄清”。

默认情况下应用使用 Mock 模式，因此不配置 API Key 也可以体验完整流程。Mock 模式适合课程展示、产品演示和离线试用。

### 6.2 创建第一个项目

在“从一个模糊想法开始”页面，用户填写最初想法。例如：

```text
我想做一个帮助大一新生在校园里快速找到教室的工具。
```

用户也可以补充：

```text
项目类型：设计类课程项目
已知限制：两周内完成，只能做移动端原型
优先澄清：目标用户、核心痛点、功能边界
```

点击“开始澄清”后，系统创建项目，进入项目工作台。

### 6.3 回答第一轮追问

首次进入工作台时，系统会从 Stage 1 开始。当前澄清卡片会提示用户补充一个真实使用场景，例如：

```text
是谁，在什么时候、什么地点，遇到了什么具体不方便？
```

用户可以回答：

```text
主要是刚入学的大一新生。开学前两周他们经常在上课前 10 分钟才发现教学楼很远，而且不知道具体入口在哪，容易迟到。
```

发送后，系统会抽取目标用户、痛点和使用场景，并更新阶段进度。

### 6.4 查看 Design Brief 是否准确

用户可以展开 Design Brief 面板，查看字段是否被正确提取。例如：

- 目标用户：刚入学的大一新生；
- 核心痛点：不熟悉教学楼位置和入口，容易迟到；
- 使用场景：开学前两周、上课前、寻找教室。

如果字段正确，用户可以确认；如果不准确，可以直接编辑或标记为需要修正。

### 6.5 继续跟随 AI 追问

系统会根据已更新的 Brief 生成下一轮问题。后续可能进入价值、差异化、边界或功能拆解等阶段。

用户每次回答后，都会重复以下循环：

```text
回答
→ 抽取字段
→ 更新进度
→ 记录轨迹
→ 推荐资源
→ 生成下一问
```

如果用户不知道怎么回答，可以点击“我还不确定”。系统会先给一条思考线索，再只问一个更具体的问题。

### 6.6 使用资源线索辅助思考

当某轮问题背后使用了设计方法，用户可以打开“本轮设计依据”或资源线索面板，查看系统为什么这样问。

例如，在边界阶段，系统可能参考 MVP 或影响-努力矩阵，提醒用户区分“第一版必须做”和“后续可以做”。

### 6.7 查看思维树

随着对话推进，用户可以进入“思维树”视图。思维树会显示：

- 项目初始想法；
- 当前阶段；
- 已产生的问题链；
- 已形成的判断；
- 被填充的字段；
- 回溯后保留的旧分支。

用户可以点击节点查看详情，也可以通过缩放和平移观察整体结构。

### 6.8 查看进度、成果和作品档案

当项目逐渐成型后，用户可以：

- 在“进度”视图查看 9 阶段完成情况；
- 在“成果”视图查看成熟度、澄清地图、MVP 边界和风险矩阵；
- 在“作品档案”视图查看设计旅程、证据墙和学习反思；
- 在“洞察”视图查看完整 Design Brief。

这些视图帮助用户从不同角度检查项目是否已经足够清晰。

### 6.9 完成项目

当 9 阶段完成，或系统判断项目已经形成较完整的设计简报时，工作台会出现完成态卡片。

用户可以：

- 查看完成后的 Brief；
- 回到上一阶段继续修正；
- 继续优化；
- 导出报告。

项目完成并不意味着不能继续修改。用户仍可通过对话、字段编辑和阶段回看继续迭代。

### 6.10 导出报告或项目包

点击“导出报告”后，用户可以选择导出格式：

- PDF：适合提交和评审；
- Markdown：适合继续编辑；
- JSON：适合备份和数据迁移；
- `.codesign`：适合保留完整可交互项目过程。

若选择 `.codesign`，文件中会包含完整设计过程、思维树、回溯分支、Design Brief 和资源线索。之后可以在首页导入该项目包，进行只读预览或导入为新项目。

### 6.11 切换到真实 API

如果需要使用真实模型，用户进入设置页：

1. 切换服务模式或填写 API 配置；
2. 输入 API Key；
3. 填写 Base URL；
4. 填写模型名；
5. 选择 Thinking Type；
6. 点击“测试 API Key”；
7. 测试成功后自动切换到 Live 模式。

常见配置示例：

```text
DeepSeek
Base URL: https://api.deepseek.com
Model: deepseek-v4-flash
Thinking Type: disabled
```

```text
百炼 DashScope
Base URL: https://dashscope.aliyuncs.com/compatible-mode/v1
Model: qwen-plus / qwen-turbo / qwen-max
Thinking Type: 不发送
```

## 7. v1.0 的完整用户闭环

CoDesign Agent v1.0 的完整闭环是：

```text
创建项目
→ 输入模糊想法
→ 回答 AI 追问
→ 系统抽取 Design Brief
→ 用户确认或修正字段
→ 阶段进度自动推进
→ 思维树记录问题链和回溯分支
→ 学习轨迹记录设计思维动作
→ 成果看板和作品档案组织展示材料
→ 导出报告或 .codesign 项目包
→ 继续迭代或提交评审
```

这个闭环让应用同时承担三种角色：

- 设计澄清助手：帮助用户把想法问清楚；
- 过程记录工具：记录用户如何一步步形成判断；
- 课程成果生成器：输出可展示、可提交、可复盘的设计材料。

## 8. 使用建议

1. 不要一开始就追求完整答案  
   先写一个真实但粗糙的想法，系统会逐步追问。

2. 尽量回答具体场景  
   “学生不方便”不如“新生上课前 10 分钟找不到教学楼入口”有用。

3. 经常查看 Design Brief  
   AI 抽取不一定总是准确，用户确认和修正是必要步骤。

4. 卡住时使用“我还不确定”  
   这个操作会触发线索式追问，比硬想答案更适合学习。

5. 不要害怕回溯  
   旧分支会被保留，修正判断本身也是设计过程的一部分。

6. 在导出前查看成果看板和作品档案  
   它们能帮助用户发现项目定义、边界、风险或指标是否仍有缺口。

7. 真实 API 使用前先测试连接  
   设置页的 API Key 测试可以避免进入对话后才发现配置错误。

## 9. v1.0 总结

CoDesign Agent v1.0 已经形成从“模糊想法”到“结构化设计简报”的完整产品闭环。它通过 9 阶段规则框架保证推进方向，通过 LLM 对话保持灵活追问，通过结构化抽取把自由回答转为 Design Brief，通过思维树和学习轨迹保留设计过程，再通过成果看板、作品档案和多格式导出支持课程提交与复盘。

它的核心价值不是让用户少思考，而是让用户更会思考：在 AI 的帮助下，把一个含混的项目念头逐步澄清为可讨论、可执行、可评审的设计方案。
