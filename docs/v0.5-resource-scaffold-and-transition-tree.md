# CoDesign Agent v0.5 说明文档

**日期**: 2026-06-09  
**版本定位**: 资源卡驱动的线索式苏格拉底追问 + 阶段连线问题链思维树  
**范围约束**: 不新增后端依赖，不修改 SwiftData 数据模型，不改成果看板、作品档案夹、VisualBoard 等展示主线

---

## 01. 版本目标

v0.5 聚焦 CoDesign Agent 的两条主线能力：

1. 当前澄清卡片从“普通追问 / 选项式提示”升级为“线索 + 提问”的苏格拉底式脚手架。
2. 思维树从“点击阶段展开内容”升级为“点击相邻阶段连线展开阶段间问题链”。

这版的产品定位不是让 AI 直接替用户写 Design Brief，也不是把设计任务变成表单选择题，而是让 Agent 在用户卡住时提供一条可理解的设计思考线索，再继续提出一个开放问题，帮助用户自己做判断。

核心原则：

```text
线索不是答案。
线索不是选项。
线索是帮助用户继续思考的认知支架。

提问不是填表。
提问不是选择题。
提问必须让用户自己做判断。
```

## 02. 产品逻辑总览

### 2.1 当前澄清流程

```text
用户输入 / 快捷按钮
        ↓
ClarificationMode.detect(...)
        ↓
ChatViewModel 统一选择 ResourceCards
        ↓
LLMService.streamChat(... mode, resourceCards)
        ↓
SocraticPromptTemplates 注入当前模式与资源卡
        ↓
AI 输出普通追问或“线索 + 追问”
        ↓
ThinkingMoment 记录 answer / method / question
```

### 2.2 思维树流程

```text
Root / 初始想法
   │  transitionOrder = 1
Stage 1
   │  transitionOrder = 2
Stage 2
   │  transitionOrder = 3
Stage 3
```

一个 `ThinkingMoment.stageOrder == n` 的节点被视为“进入 Stage n 的过程中产生的问题链”，而不是 Stage n 节点本身的右侧附属内容。

## 03. “线索 + 提问”模式

### 3.1 新增 ClarificationMode

新增文件：

```text
CoDesign-Agent/Services/Dialogue/ClarificationMode.swift
```

当前枚举：

```swift
enum ClarificationMode {
    case normal
    case stuckScaffold
    case exampleRequested
    case reframe
    case boundaryDraft
    case skip
}
```

触发 `stuckScaffold` 的输入包括：

```text
我还不确定
不确定
我不知道
不知道
想不出来
没想好
卡住了
不会答
没有思路
没思路
没想法
```

`CurrentClarificationCard` 中“我还不确定”快捷按钮也会发送严格提示，要求进入“线索 + 提问”模式，不给 A/B/C 选项，不替用户回答。

---

### 3.2 资源卡选择策略

核心文件：

```text
CoDesign-Agent/Services/ResourceRecommendationService.swift
CoDesign-Agent/Models/ResourceCard.swift
CoDesign-Agent/Services/ResourceLibrary.swift
```

普通模式下，资源推荐仍基于：

- 当前阶段；
- DesignBrief 缺失字段；
- 用户最新输入；
- resource tags / problemTypes / relatedFields；
- StageDefinition 推荐卡片。

`stuckScaffold` 模式下，会额外偏向以下资源：

- `scaffoldingStrategy`
- `questionStrategy`
- `cognitiveDepth`
- `method`
- 与当前阶段相关的 `content`

每轮由 `ChatViewModel` 统一选择资源卡：

- stuck 模式最多 2 张；
- 普通模式最多 5 张；
- 选中的同一批卡传给 LLM；
- 过程记录使用同一批卡的首张卡；
- 避免“记录了一张卡，但 prompt 用的是另一批卡”的不一致。

---

### 3.3 LLMService 协议调整

核心文件：

```text
CoDesign-Agent/Services/Protocols/LLMServiceProtocol.swift
CoDesign-Agent/Services/Live/LiveLLMService.swift
CoDesign-Agent/Services/Mock/MockLLMService.swift
```

`LLMServiceProtocol.streamChat` 已增加：

```swift
mode: ClarificationMode
resourceCards: [ResourceCard]
```

`LiveLLMService` 不再自行重新推荐资源卡，而是使用 `ChatViewModel` 传入的卡片构建 prompt。`MockLLMService` 也实现同样的模式分支，用于本地 fallback 和预览。

---

### 3.4 Prompt 约束

核心文件：

```text
CoDesign-Agent/Services/Prompts/SocraticPromptTemplates.swift
CoDesign-Agent/Services/Dialogue/DesignDialoguePlanner.swift
```

普通模式：

- 每轮只问 1 个关键问题；
- 不默认输出 A/B/C；
- 不直接替用户决定；
- 不重复已经回答过的问题。

`stuckScaffold` 模式强制输出：

```text
线索：
[基于资源卡转译出的、和用户当前项目相关的思考方法。不要超过 3 行。]

追问：
[一个开放但具体的问题。必须只有一个问题。]
```

严格禁止：

- A/B/C 选项；
- 编号选项；
- “你可以选择……”；
- “以下是几个方向……”；
- 直接给完整答案；
- 直接生成 Design Brief；
- 大段讲资源卡标题、论文名、作者名；
- 让用户机械填写字段。

`DesignDialoguePlanner` 中历史遗留的 A/B/C `options` 数据已移除，避免后续实现误用。

---

### 3.5 过程记录

核心文件：

```text
CoDesign-Agent/ViewModels/ChatViewModel.swift
CoDesign-Agent/Models/ThinkingMoment.swift
CoDesign-Agent/Views/ProjectDetail/ProcessLogDisclosure.swift
```

每轮对话继续复用 `ThinkingMoment`，不新增 SwiftData 模型，避免 migration 风险。

在 stuck 模式中会记录：

| momType | 内容 |
|---|---|
| `answer` | 用户输入，例如“我还不确定” |
| `method` | 调用方法、触发原因、线索作用、生成问题、期望字段 |
| `question` | AI 最终提出的问题 |

`method` 内容结构：

```text
调用方法：xxx
触发原因：用户不确定 / 当前字段缺失 / 当前阶段卡住
线索作用：帮助用户从 xxx 角度重新理解当前问题
生成问题：xxx
期望字段：xxx
```

## 04. 当前澄清卡片 UI

核心文件：

```text
CoDesign-Agent/Views/ProjectDetail/CurrentClarificationCard.swift
CoDesign-Agent/Views/Components/ResourceCardPanel.swift
```

### 4.1 方法资源卡

资源卡面板仍然保留在当前澄清区域上方，但只是轻量提示：

- 默认折叠；
- 展开后才显示方法说明；
- 不作为主界面核心；
- stuck 模式下显示“本轮使用方法线索辅助追问”。

### 4.2 快捷按钮

“我还不确定”按钮保留，但行为改为：

```text
我还不确定。请进入“线索 + 提问”模式：
先基于当前阶段和方法资源卡给我一条能理解的思考线索，
再只问一个开放问题。不要给 A/B/C 选项，不要直接替我回答。
```

“给我一个例子”不再默认立刻出现，而是在当前澄清卡片有 AI 回复后延迟显示，用于避免用户一开始就进入例子选择。

### 4.3 AI 文本展示

当前澄清卡片的 AI 回复展示已统一：

- streaming 和 final 使用同一个 `StructuredAssistantText`；
- 不再出现“生成中纯文本，生成完重新排版”的跳变；
- 不显示语义圆点；
- 标签以内联文本呈现，例如 `线索：...`、`追问：...`；
- 空行只作为内部分段信号，不渲染成奇怪的大段空白；
- 长文本交给 SwiftUI 自然换行，不按句号硬拆。

## 05. 思维树：阶段连线展开问题链

核心文件：

```text
CoDesign-Agent/Views/MindTree/ThinkingTreeView.swift
CoDesign-Agent/Views/MindTree/TreeModels.swift
CoDesign-Agent/Views/MindTree/TreeLayoutEngine.swift
CoDesign-Agent/Views/MindTree/TreeNodeView.swift
CoDesign-Agent/Views/MindTree/ThinkingNodeDetailSheet.swift
CoDesign-Agent/Views/MindTree/NodeEditSheet.swift
```

### 5.1 展开语义

v0.5 将展开状态从 stage 语义改为 transition 语义：

```swift
@State private var expandedTransitionOrders: Set<Int>
```

含义：

| transitionOrder | 表示 |
|---|---|
| 1 | Root / 初始想法 → Stage 1 |
| 2 | Stage 1 → Stage 2 |
| 3 | Stage 2 → Stage 3 |
| n | Stage n-1 → Stage n |

`TreeEdge` 中使用：

```swift
togglesTransitionOrder: Int?
```

每条主干边都带有对应的 `togglesTransitionOrder`，点击连线时展开或收起该阶段间的问题链。

---

### 5.2 TreeBuilder

`TreeBuilder.build(...)` 现在根据：

```swift
expandedTransitionOrders.contains(moment.stageOrder)
```

决定是否显示过程节点。

展开 transitionOrder = n 时显示：

- `question`
- `answer`
- `method`
- `decision`
- `evidence`
- `revision`
- learning trace

这些节点被理解为“进入 Stage n 的过程中产生的思考链”。

节点语义：

| momType | 树节点 |
|---|---|
| `question` | Q / 问题节点 |
| `answer` | A / 用户回答 |
| `method` | 线索 |
| `decision` / `deepen` | Decision |
| `evidence` | Evidence |
| 非活跃分支 | Revision / 旧版本 |

---

### 5.3 Transition Corridor Layout

`TreeLayoutEngine` 现在采用 corridor layout：

1. 找到上一个主干节点：
   - n == 1：Root；
   - n > 1：Stage n-1。
2. 找到当前 Stage n。
3. 将 `stageOrder == n` 的过程节点排在二者之间。
4. question 节点靠近主干显示；
5. answer / method / decision / evidence 等侧向节点围绕问题节点或主干排布；
6. 节点多时增加阶段间距，避免全部挤在一个 stage 旁边。

目标效果：

```text
Stage 1
   │
   Q
  A / 线索 / Decision
   │
   Q
  A / Evidence
   │
Stage 2
```

---

### 5.4 交互行为

| 操作 | v0.5 行为 |
|---|---|
| 点击 Stage 节点 | 只选择节点 / 显示详情，不展开问题堆 |
| 点击相邻阶段主干连线 | 展开 / 收起该 transition 的问题链 |
| 再次点击同一连线 | 收起 |
| 长按可编辑节点 | 进入回溯修改 |
| 点击 evidence 资源 | 可采纳为证据节点 |
| 缩放 / 拖拽 | 保留视图导航能力 |

连线标签：

```text
点击展开问题链
已展开 · n 个节点
```

展开时会保持当前连线锚点在屏幕中的位置，避免点击后视图突然跳到奇怪的位置。

---

### 5.5 回溯与旧版本分支

回溯仍复用现有 `ThinkingMoment` 字段：

- `isActiveBranch`
- `branchVersion`
- `parentMomentID`

编辑节点时，旧节点和受影响子节点会转为非活跃分支，并以低透明度 / 灰色 / 虚线风格显示。新的修改节点留在当前活跃分支中。

这样用户能看到：

```text
当前版本：继续推进
旧版本：灰色旁支保留为历史痕迹
```

## 07. 验收标准

### 7.1 线索 + 提问

输入：

```text
我还不确定
```

期望：

```text
线索：
……

追问：
……？
```

必须满足：

- 只问一个问题；
- 不出现 A/B/C；
- 不直接替用户生成答案；
- 线索和当前项目主题有关；
- 线索能看出来自资源卡 / 方法论的转译；
- `ThinkingMoment` 中记录 answer / method / question。

### 7.2 普通追问

正常回答时：

- 不强制每轮输出 `线索：`；
- 继续阶段推进；
- 只问 1 个关键问题；
- 不重复问已经回答过的问题。

### 7.3 当前澄清卡片文本

- streaming 和完成态使用同一套排版；
- 不出现完成后突然重排成大空行版本；
- 不显示额外彩色圆点；
- 文本使用卡片完整宽度自然换行；
- 行间距和段落间距保持一致。

### 7.4 思维树

- 默认不会展开全部节点；
- Stage 主链清晰；
- 点击 Stage 节点不会展开一大堆内容；
- 点击阶段间连线只展开对应 transition 的问题链；
- 再点一次可收起；
- 问题节点位于两个阶段之间；
- 旧版本 / 回溯节点保持灰色、虚线、低透明度。

## 09. 已知风险与后续优化

### 已知风险

- LLM 仍可能偶发不完全遵守 prompt，需要继续观察真实模型输出；
- 资源卡推荐依赖关键词和缺失字段打分，后续可引入更细的 trigger 信号；
- 当前 `ThinkingMoment` 复用字符串字段记录 method 内容，结构轻量但不适合复杂统计；
- 思维树节点多时仍需继续优化拥挤场景下的布局密度。

### 后续优化方向

- 为 stuckScaffold 增加轻量单元测试或 snapshot 测试；
- 在 Process Log 中更清晰展示“触发原因 → 调用卡片 → 生成问题”；
- 为思维树 transition 展开增加节点数量阈值和分页/折叠策略；
- 为资源卡 UI 增加“本轮实际使用”与“推荐但未使用”的轻量区分；
- 在真实 iOS Simulator 中验证 streaming 文本排版稳定性。
