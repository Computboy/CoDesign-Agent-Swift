# CoDesign Agent 使用说明书

**适用版本**: v0.3.3  
**适用对象**: 设计类课程学生、创新创业课程学生、指导教师、项目演示者  
**核心用途**: 帮助用户从模糊项目想法出发，逐步澄清设计问题、范围、方案与验收标准。

---

## 01. App 是做什么的

CoDesign Agent 是一个设计思维训练型 AI 工作台。你输入一个还不成熟的项目想法，AI 会通过追问帮助你一步一步想清楚：

- 为谁设计；
- 解决什么问题；
- 在什么场景中发生；
- 项目边界是什么；
- MVP 需要包含哪些功能；
- 如何判断项目成功；
- 风险和阶段计划是什么。

App 的目标不是替你直接生成答案，而是帮助你把设计判断说清楚、写下来、形成结构化设计简报。

---

## 02. 推荐使用流程

```text
新建项目
→ 输入一个模糊想法
→ 在工作台回答 AI 追问
→ 查看右侧 Design Brief 字段
→ 确认或修正字段
→ 跟随 9 阶段推进
→ 完成后导出设计简报
```

你不需要一开始就想得很完整。一个好的起点可以很简单，例如：

```text
我想做一个帮助大一新生在校园里快速找到教室的工具。
```

## 03. 项目列表页

打开 App 后，首先进入项目列表页。

你可以在这里：

- 查看已有项目；
- 搜索项目；
- 新建项目；
- 进入设置页配置 API；
- 点击项目卡片进入 Project Detail 工作台。

项目卡片通常会展示：

- 项目名称；
- 简短描述；
- 当前阶段；
- 完成进度；
- 更新时间。

---

## 04. 新建项目

点击项目列表页右上角的 `+` 创建新项目。

建议填写：

- **我现在的设计想法是**：必填，写下你的初始想法；
- **项目类型**：可选，例如课程项目、创新创业项目、个人 App 想法；
- **已知限制**：可选，例如时间、技术、团队人数、预算；
- **澄清优先级**：可选，例如目标用户、核心痛点、功能边界。

点击“开始澄清”后，App 会进入项目工作台。

---

## 05. Project Detail 工作台

Project Detail 是主要工作区。v0.3.3 采用三栏结构：

```text
左侧：阶段流程
中间：当前协作焦点
右侧：Design Brief 字段
```

### 左侧：阶段流程

左侧展示 9 阶段设计流程。

你可以用它判断：

- 当前处于哪个阶段；
- 哪些阶段已经完成；
- 哪些阶段还未开始；
- 当前阶段的目的是什么。

淡色纵向连接线表示流程连续性；当前阶段会以轻微高亮显示。

### 中间：当前协作焦点

中间是你和 AI 协作的主区域。

这里包括：

- 当前阶段名称；
- AI 的当前追问；
- 追问意图；
- 可能更新的 Design Brief 字段；
- 回答输入框；
- 快捷操作；
- 学习轨迹；
- 过程记录。

你可以直接输入回答，也可以使用快捷操作。

### 右侧：Design Brief 字段

右侧展示当前已提取的结构化字段，例如：

- 目标用户；
- 核心痛点；
- 使用场景；
- 核心价值；
- MVP 功能；
- 验收标准。

每张字段卡可以：

- 点击“编辑”手动修改；
- 点击“确认”标记字段可信；
- 点击 warning 图标标记不准确；
- 右滑快速确认；
- 左滑快速标记不准确。

确认状态会显示左侧绿色状态竖线；需修正状态会显示左侧 warning 状态竖线。

## 06. 快捷操作说明

当前澄清卡片下方提供几个快捷操作：

| 操作 | 适合场景 |
|------|----------|
| 给我一个例子 | 不知道应该怎么回答时 |
| 我还不确定 | 想让 AI 把问题拆得更简单 |
| 换个角度问 | 当前提问方式不够清楚 |
| 生成边界草稿 | 已有一些信息，希望先形成 MVP 范围草稿 |
| 跳过 | 当前问题暂时无法回答，希望继续推进 |

快捷操作不会替你最终决定项目，只是帮助你更容易进入下一轮思考。

---

## 07. 学习轨迹

学习轨迹用于记录你在设计思维上的关键动作。

常见记录包括：

- 你锚定了痛点场景；
- 你提炼了差异价值；
- 你收缩了项目范围；
- 你明确了验收标准；
- 你识别了核心风险。

这些记录帮助你回顾项目是如何一步步变清晰的，也适合用于课程汇报或过程反思。

---

## 08. 过程记录

过程记录是一个可折叠区域，用于查看对话历史。

它适合用来：

- 回顾 AI 问过什么；
- 检查自己之前如何回答；
- 理解某个字段为什么被提取出来；
- 为课程过程记录提供依据。

默认情况下，过程记录不抢占主要视觉空间。

---

## 09. 完成态与导出

当 9 阶段完成，或系统判断项目已经进入完整简报状态时，中间会出现“设计简报已完成”主卡片。

完成态卡片会展示：

- 完成状态；
- Brief Snapshot；
- 更新时间；
- 导出简报主操作；
- 查看简报、回到上一阶段、继续优化等次级操作。

当前版本中，“导出简报”是主操作入口。后续可以继续扩展为 Markdown、PDF 或系统分享。

## 10. Tabs 说明

Project Detail 里包含多个视图：

| Tab | 用途 |
|-----|------|
| 工作台 | 默认主视图，包含三栏协作体验 |
| 对话 | 更传统的聊天记录视图 |
| 进度 | 查看 9 阶段完成情况 |
| 洞察 | 查看完整设计简报与学习轨迹 |

日常使用建议优先停留在“工作台”。

## 11. Mock 模式与 Live 模式

### Mock 模式

Mock 模式是默认模式。

特点：

- 不需要 API Key；
- 可离线演示；
- 回复和提取结果由本地 mock 服务生成；
- 适合开发、课堂展示、UI 调试。

### Live 模式

Live 模式会调用真实 LLM API。

你需要在设置页填写：

- API Key；
- Base URL；
- Model；
- Thinking Type。

示例：

```text
Base URL: https://api.deepseek.com
Model: deepseek-v4-flash
Thinking Type: disabled
```

或：

```text
Base URL: https://dashscope.aliyuncs.com/compatible-mode/v1
Model: qwen-plus
Thinking Type: 不发送
```

Live 服务失败时，系统应降级到 Mock 服务，保证基本流程可继续。

## 12. 如何写一个好回答

回答 AI 追问时，不需要写得很正式，但建议尽量具体。

不太好的回答：

```text
给学生用，帮助学习。
```

更好的回答：

```text
主要给刚入学的大一新生用。场景是开学第一周，他们需要在 10 分钟内从宿舍赶到陌生教学楼，但不熟悉建筑名字和路线。
```

一个好回答通常包含：

- 具体人群；
- 具体场景；
- 当前困难；
- 已知限制；
- 暂时不做的内容；
- 可衡量的目标。

## 13. 常见问题

### 为什么 AI 一直追问，不直接给完整方案？

因为 App 的目标是训练设计思维。AI 的角色是引导你做判断，而不是直接替你完成项目。

### 右侧字段不准确怎么办？

点击字段卡上的编辑按钮手动修改，或点击 warning 图标标记不准确。后续对话中也可以继续补充。

### 为什么某些字段还没有出现？

字段是从对话中逐步提取的。还没有足够信息时，字段会保持未提取状态。

### 可以跳过某个问题吗？

可以。点击“跳过”，AI 会根据已有信息继续推进到下一个合理澄清点。

### Live 模式没有回复怎么办？

检查：

- API Key 是否正确；
- Base URL 是否是 OpenAI-compatible endpoint；
- Model 名称是否可用；
- Thinking Type 是否被当前 provider 支持；
- 网络权限是否允许出站连接。

## 14. 给教师或演示者的建议

课堂演示时建议使用 Mock 模式，保证流程稳定。

推荐演示路径：

1. 新建一个模糊项目想法；
2. 回答 2-3 轮 AI 追问；
3. 展示右侧字段如何自动提取；
4. 手动编辑一个字段；
5. 确认一个字段；
6. 展示学习轨迹；
7. 展示 9 阶段进度；
8. 说明完成态 Brief Snapshot 与导出入口。

这样能清楚说明 App 的核心价值：它不是替学生写作业，而是让学生看见并练习自己的设计判断。

```bash

  -destination 'platform=iOS Simulator,id=7E83E99D-AA67-488D-B2CC-F1F1DF77EAF8' \
  build
```

该 UUID 对应：

```text
iPhone 17 Pro
iOS 26.4
```

```bash
xcodebuild -scheme CoDesign-Agent \
  -destination 'platform=macOS' \
  build
```
