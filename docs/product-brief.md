# 一、项目背景

我们正在完成《信息与交互设计技术》课程大作业，需要开发一个团队可独立完成的 iOS App。课程要求包括：

* 使用 SwiftUI 开发；
* 至少包含列表页 List、新增页 Add、详情页 Details；
* 数据需要本地持久化，无需后端、登录、云同步；
* 需要有统一设计语言、自定义组件、手势交互、动画效果、视觉反馈；
* 最终提交包括功能演示、设计文档、项目说明、任务拆分、源代码。

我们目前的产品方向是：

**一个面向设计类学生 / 智能硬件项目初学者的苏格拉底式设计思维训练 Agent App。**

它不是单纯帮用户生成开题报告，也不是一个死板的表单工具，而是通过 AI 对话帮助用户在项目前期把模糊创意逐步澄清为：

* 清晰的用户痛点；
* 真实使用场景；
* 差异化核心价值；
* 明确项目边界；
* 可落地的软硬件 / 交互 / 算法方案；
* 运行逻辑与异常处理；
* 硬性约束；
* 量化验收标准；
* 风险预案；
* 阶段排期。

最终，用户获得的不只是一个开题文档，而是完成了一次“设计思维训练”。

# 二、核心产品判断

我们已经意识到一个关键问题：

如果把 AI Agent 做成“按照标准步骤填表”的状态机，它会大幅削弱大语言模型的智能。
因为真实的设计思考不是线性填表，而是反复发散、收缩、回溯、修正的过程。

因此，我们决定采用：

**底层刚性规则框架 + 上层 LLM 柔性自由对话 + 中间结构化提取层**

具体来说：

## 1. 底层刚性规则框架

底层保留一套专业的设计项目前期澄清逻辑，确保产品不会跑偏。

推荐流程为 9 个阶段：

1. 痛点与场景锚定
2. 差异化价值提炼
3. 项目边界划定
4. 功能与技术方案拆解
5. 运行逻辑与规则定义
6. 硬性约束设计
7. 量化验收标准制定
8. 风险识别与预案制定
9. 项目阶段拆分与排期

但注意：
这 9 步不应该被设计成“不可逆的状态机”。
更合理的方式是：

**默认推荐路径是顺序推进，但用户可以随时回溯、修改、重构前序节点。系统需要在用户修改后自动提示哪些后续内容需要重新校验。**

## 2. 上层 LLM 柔性自由对话

用户看到的不是表单，而是一个轻松、自然的聊天界面。

AI 通过苏格拉底式提问引导用户思考，例如：

* “你觉得这个问题具体发生在哪类用户身上？”
* “如果只能保留三个核心功能，哪些必须留下？”
* “这个功能解决的是核心痛点，还是只是听起来很酷？”
* “如果这个方案失败，最可能是技术失败、用户不买账，还是边界定义太泛？”
* “你如何证明这个产品确实解决了问题？”

AI 不应该直接替用户给出完整答案，而是通过追问、总结、反问、比较，帮助用户自己把问题想清楚。

## 3. 中间结构化提取层

虽然用户在自由聊天，但系统后台需要从对话中自动提取结构化信息，存入字段，例如：

* targetUser
* useScenario
* painPoint
* coreValue
* differentiation
* mvpFeatures
* excludedFeatures
* technicalModules
* interactionFlow
* hardConstraints
* successMetrics
* risks
* mitigationPlans
* milestones

这些字段用于：

* 项目进度可视化；
* 缺失信息诊断；
* 自动生成项目边界表；
* 自动生成风险矩阵；
* 自动生成设计开题 Markdown；
* 后续扩展为 PDF 导出。

# 三、产品定位

请不要把这个产品写成：

“AI 帮你写智能硬件开题报告的工具。”

更准确的定位应该是：

**一个面向设计类学生的苏格拉底式设计思维训练 Agent，帮助用户在项目前期把模糊创意转化为清晰的设计问题、项目边界、技术路径与风险闭环。**

开题报告只是最终副产物。
真正的核心价值是：

**让用户在与 AI 的对话中完成设计思维训练，并把原本不可见的思考过程可视化。**

# 四、核心设计原则

请围绕以下原则优化方案：

## 原则 1：框而不死，活而不乱

系统底层有清晰框架，但前台交互不应像填表。
用户体验应该是自由聊天，但系统后台始终知道当前项目缺什么、偏到哪里、哪些字段尚未补全。

## 原则 2：AI 不替用户思考，而是训练用户思考

不要让 Agent 直接给答案。
Agent 应该帮助用户完成：

* 问题定义；
* 价值判断；
* 边界收缩；
* 功能取舍；
* 风险意识；
* 验收标准制定。

## 原则 3：视觉化呈现认知过程

为了体现这是一个智能产品，而不是普通聊天机器人，必须把用户的设计思考过程可视化。

建议至少包含：

* 9 步流程进度图；
* 关键缺失信息提示；
* 项目边界表；
* 风险矩阵；
* 开题报告结构预览。

## 原则 4：先做 MVP，不要功能爆炸

V1.0 不要追求大而全。
优先保证核心闭环跑通：

用户输入模糊创意
→ AI 苏格拉底式追问
→ 后台结构化提取
→ 缺失信息诊断
→ 流程节点逐步点亮
→ 自动生成项目边界表和风险矩阵
→ 导出 Markdown 开题报告
