# CoDesign Agent v0.8 说明文档

**日期**: 2026-06-12  
**版本定位**: 多尺寸工作台适配 + 思维树回溯分支表达 + 项目库独立页 + API Key 自检 + iOS 触控可用性 polish  
**范围约束**: 不新增后端，不改变 SwiftData 核心模型，不重做 RAG / Prompt 主流程，不把工作台改回普通聊天页

---

## 01. 版本目标

v0.8 是一次围绕“真实设备可用性”和“设计过程可解释性”的体验巩固版本。

v0.5.2 已经完成了轻量本地 RAG、自然导师式追问、首页视觉重绘和工作台排版修复。v0.8 在此基础上继续解决三个更贴近日常使用的问题：

1. 工作台在 iPhone、iPad 竖屏、iPad 横屏、桌面宽屏下都要有合适结构，而不是只服务单一大屏三栏布局。
2. 思维树不仅展示当前主线，也要能表达回溯后留下的旧分支，并且在展开问题链时减少节点重叠和连线混乱。
3. 首页只展示最近项目，完整项目管理进入独立项目库；设置页可以直接测试当前 API 配置是否可用。

核心原则：

```text
小屏不是缩小版桌面，而是需要把辅助信息收进可打开的面板。
旧分支不是噪音，而是设计推理过程的一部分。
项目首页负责启动和回到最近工作，项目库负责完整管理。
API 配置应该能被用户立即验证，而不是等到聊天失败后才发现问题。
```

## 02. 工作台多尺寸布局

核心文件：

```text
CoDesign-Agent/Views/ProjectDetail/ClarificationWorkspaceView.swift
CoDesign-Agent/Views/ProjectDetail/WorkspaceGlobalBar.swift
CoDesign-Agent/Views/ProjectDetail/StageRail.swift
CoDesign-Agent/Views/ProjectDetail/CurrentClarificationCard.swift
```

### 2.1 布局模式拆分

`ClarificationWorkspaceView` 不再只用 `horizontalSizeClass` 判断宽窄，而是基于 `GeometryReader` 拆分为四种模式：

```swift
desktopWide
iPadLandscape
iPadStacked
narrow
```

对应行为：

| 模式 | 主要场景 | 工作台结构 |
|---|---|---|
| `desktopWide` | macOS / 桌面宽屏 | 左侧嵌入思维树，右侧当前澄清与 Brief |
| `iPadLandscape` | iPad 横屏 | 接近桌面结构，但收窄边距与树宽度 |
| `iPadStacked` | iPad 竖屏 / 中等宽度 | 顶部阶段条 + 当前工作区 + 辅助面板入口 |
| `narrow` | iPhone / 窄屏 | 阶段条、辅助入口、当前澄清纵向排列 |

这样工作台可以根据实际窗口尺寸变化，而不是仅依赖系统 size class。

### 2.2 辅助面板 Sheet 化

在 `iPadStacked` 和 `narrow` 模式下，思维树、资源线索、Design Brief 不再挤在主工作区里，而是通过 `WorkspaceAccessoryBar` 打开：

```text
思维树
资源线索
Design Brief
```

其中：

- 思维树以 `ThinkingTreeView(mode: .standalone)` 打开；
- 资源线索使用 `ResourceCardPanel(startsExpanded: true)`；
- Design Brief 使用 `InsightCardsPanel`；
- iOS 下使用 `.presentationDetents` 控制中/大尺寸面板。

主工作区因此保持聚焦：用户在小屏上优先回答当前追问，辅助信息按需查看。

### 2.3 全局工具条与阶段条可触控化

`WorkspaceGlobalBar` 增加了第三层 fallback：

```text
regularLayout -> compactLayout -> scrollableCompactLayout
```

当横向空间不足时，工具项会进入水平滚动容器，避免按钮被挤压或消失。

`StageRail` 的阶段说明从仅长按触发扩展为点击也可触发，阶段胶囊增加 `contentShape(Rectangle())`，更符合触屏设备的交互预期。

## 03. 思维树回溯分支与布局稳定性

核心文件：

```text
CoDesign-Agent/Views/MindTree/TreeModels.swift
CoDesign-Agent/Views/MindTree/TreeLayoutEngine.swift
CoDesign-Agent/Views/MindTree/ThinkingTreeView.swift
CoDesign-Agent/Views/MindTree/TreeNodeView.swift
CoDesign-Agent/Views/MindTree/ThinkingNodeDetailSheet.swift
CoDesign-Agent/Views/MindTree/NodeEditSheet.swift
```

### 3.1 新增 branchStage 节点类型

`TreeNodeKind` 新增：

```swift
case branchStage
```

用于表达折叠状态下的旧阶段分支。旧分支不再只能作为零散历史节点出现，而是可以从回溯发生的阶段向后形成一条灰色旁支。

折叠状态下：

```text
Stage 1 主线
   └─ 旧分支 Stage 2
       └─ 旧分支 Stage 3
```

展开状态下：

```text
当前核心问题
   ├─ 当前活跃回答 / 判断
   └─ 旧问题 vN
       └─ 旧答案影响的判断
```

### 3.2 旧分支锚定到可见问题

`TreeBuilder` 新增 `branchAnchorID`，用于把旧分支节点锚定到当前可见的问题节点上。

关键效果：

- 隐藏普通 answer 节点，避免思维树被“我还不确定 / 旧答案”占满；
- 保留旧答案造成的 decision / process / revision 等有效痕迹；
- 当旧分支来自某个问题时，补一个“回溯问题”节点作为旧分支入口；
- 未展开时显示旧阶段旁支，展开后显示旧问题与旧判断。

### 3.3 布局算法改为按 transition 动态分配高度

`TreeLayoutEngine` 不再用单一 `stageSpacing` 套全部阶段，而是根据每段 transition 内的问题数、侧边卡片数动态计算间距：

```swift
transitionSpacings(maxStage:nodesByStage:)
transitionSpacing(for:)
stageY(order:rootY:transitionSpacings:)
transitionStartY(order:rootY:transitionSpacings:)
```

主要解决：

- 展开某段问题链后，相邻阶段被挤在一起；
- 多个 side card 同侧重叠；
- archived 节点和当前节点混在同一竖向位置；
- 内容宽度不足导致节点贴边。

v0.8 同时调整了 side branch spacing、content width、节点估算宽度、边界 clamp 和 deterministic jitter，让思维树在嵌入模式和独立模式下都有更稳定的空间。

### 3.4 iOS 节点详情改用 Sheet

`ThinkingTreeView` 在 iOS 上不再依赖 popover 展示节点详情，而是使用：

```swift
.sheet(item: $selectedNode)
```

并提供 medium / large detents。这样在 iPhone 和 iPad 上都能获得更可靠的节点详情阅读和编辑入口。

## 04. 项目首页与项目库

核心文件：

```text
CoDesign-Agent/Views/ProjectList/CoDesignHomeView.swift
CoDesign-Agent/Views/ProjectList/ProjectListView.swift
CoDesign-Agent/Views/ProjectList/ProjectCard.swift
```

### 4.1 首页只保留最近项目

`CoDesignHomeView` 移除了 `showsAllProjects` 的就地展开逻辑。

现在首页的职责更清晰：

- 展示 hero 区与主要行动入口；
- 展示最近 3 个项目；
- 搜索时展示匹配项目；
- 当项目数量超过 3 个时，通过“查看全部”进入项目库。

这避免首页在项目变多后变成一个无限增长的管理列表。

### 4.2 新增 ProjectLibraryView

`ProjectListView.swift` 新增 `ProjectLibraryView`，作为完整项目管理页。

项目库能力：

- 独立导航标题“项目库”；
- 支持 `.searchable` 搜索项目名和 brief description；
- `LazyVGrid` 自适应多列展示；
- 可新建项目、打开设置、删除项目；
- iOS 上自定义返回按钮，带离场动画；
- 卡片进入时有逐项延迟动画。

`ProjectCard` 新增 `fixedHeight`，保证项目库网格中卡片高度稳定，避免不同项目内容长度造成瀑布式跳动。

### 4.3 首页响应式 hero 修正

`CoDesignHomeView` 的 `HomeLayout` 从只持有 `width` 改为持有完整 `size`，并新增多个布局参数：

```swift
usesStackedHero
isWideHero
showsFloatingHeroCards
heroCopyMaxWidth
heroIllustrationFrameWidth
heroIllustrationWidth
heroIllustrationHeight
```

主要修正：

- 窄屏下标题三行拆分，避免长标题被压缩得过窄；
- 中等宽度下缩小树图与浮动卡片；
- 高度不足时隐藏浮动卡片，避免视觉元素互相覆盖；
- 最近项目卡片固定高度，文字最多两行。

## 05. API Key 自检

核心文件：

```text
CoDesign-Agent/Services/API/LLMAPIClient.swift
CoDesign-Agent/Views/Settings/APISettingsView.swift
```

### 5.1 LLMAPIClient 新增 testConnection

`LLMAPIClient` 新增：

```swift
func testConnection() async throws -> String
```

它使用极小的非流式 chat completion 请求验证当前配置：

```text
Base URL
API Key
Model
Thinking Type
```

请求特点：

- `stream: false`
- `temperature: 0`
- `maxTokens: 8`
- 不依赖 `response_format`
- system prompt 要求模型只返回 `OK`

这样可以降低 token 消耗，也避免把连接测试绑死在结构化输出能力上。

### 5.2 设置页增加测试按钮与状态反馈

`APISettingsView` 新增：

```text
测试 API Key
正在测试 API Key
连接成功，模型返回：...
失败原因提示
```

状态字段：

```swift
isTestingAPI
apiTestSucceeded
apiTestMessage
```

当用户修改 API Key、Base URL、Model 或 Thinking Type 时，会自动清除上一次测试结果，避免旧状态误导当前配置。

## 06. iOS 输入与触控细节

核心文件：

```text
CoDesign-Agent/Views/ProjectDetail/AnswerComposer.swift
CoDesign-Agent/Views/ProjectDetail/ChatPanel.swift
CoDesign-Agent/Views/ProjectDetail/CurrentClarificationCard.swift
CoDesign-Agent/Views/ProjectDetail/EditableInsightCard.swift
CoDesign-Agent/Views/ProjectDetail/InsightCardsPanel.swift
CoDesign-Agent/Views/Components/ResourceCardPanel.swift
CoDesign-Agent/Views/Components/StageExplanationPopover.swift
```

本版本对多个小控件做了 iOS 触控尺寸修正：

- 发送按钮在 iOS 下增大到 44pt；
- 快捷操作按钮在 iOS 下增高到 40pt；
- 字段确认 / 回退按钮在 iOS 下增高到 36pt；
- Stage 说明关闭按钮扩大到 44pt；
- ResourceCardPanel header 在 iOS 下最小高度为 44pt；
- 输入框增加 `.submitLabel(.send)`；
- iOS 下关闭发送后自动 refocus，避免键盘反复抢焦点；
- ScrollView 增加交互式键盘收起。

这些改动不改变业务逻辑，但明显改善触屏环境下的误触、焦点跳动和按钮过小问题。

## 09. 保留与未做

本版本明确没有做：

- 没有新增后端服务；
- 没有新增登录或账号系统；
- 没有新增实时多人协作；
- 没有修改 SwiftData 核心模型；
- 没有改变 v0.5.2 的本地 RAG 主流程；
- 没有把 API Key 改为 Keychain 存储；
- 没有把项目库做成标签、归档、批量操作系统；
- 没有引入完整的视觉画布编辑能力。

后续仍需注意：

- API Key 仍通过 `@AppStorage` 存储，安全性不如 Keychain；
- `ProjectLibraryView` 已具备完整列表入口，但还没有归档、排序切换和批量删除；
- 思维树旧分支表达已经可视化，但复杂项目中仍可能需要更强的过滤、折叠和搜索能力；
- iPad / iPhone 布局已有响应式结构，但仍建议在真实设备和不同 Split View 宽度下继续做视觉 QA。
