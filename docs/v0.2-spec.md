# CoDesign Agent v0.2 — Live API 接入技术规格

> **版本定位：** v0.2 不是重做产品，也不是扩展成完整后端系统，而是在 v0.1 Mock-first 核心闭环已经跑通的基础上，把 Mock LLM / Mock Extractor 替换为真实 LLM API，并保留 Mock fallback。
>
> **v0.2 目标：** 用户输入模糊设计想法后，系统可以调用真实大模型进行苏格拉底式追问，并调用真实大模型进行结构化字段提取，从而继续驱动 DesignBrief、9 阶段进度、LearningTrace 与 InsightsPanel 更新。
>
> **核心原则：** 不破坏 v0.1，先打通 Live API 最小闭环，再考虑 UI 设置页、导出、复杂错误处理等扩展功能。

## 四、API 配置设计

### 1. LLMAPIConfig

新增文件：

```text
Services/API/LLMAPIConfig.swift
```

职责：

* 读取 API baseURL
* 读取 API key
* 读取 model
* 读取 serviceMode
* 不在代码中硬编码真实 API key
* 支持默认值
* 支持缺失 key 时 fallback

建议结构：

```swift
import Foundation

struct LLMAPIConfig {
    let baseURL: URL
    let apiKey: String
    let model: String
    let timeoutSeconds: TimeInterval

    var chatCompletionsURL: URL {
        baseURL.appending(path: "chat/completions")
    }

    var isValid: Bool {
        !apiKey.trimmingCharacters(in: .whitespacesAndNewlines).isEmpty
    }

    static func loadFromEnvironment() -> LLMAPIConfig {
        let env = ProcessInfo.processInfo.environment

        let baseURLString =
            env["LLM_BASE_URL"]
            ?? env["DEEPSEEK_BASE_URL"]
            ?? "https://api.deepseek.com"
        let apiKey =
            env["LLM_API_KEY"]
            ?? env["DEEPSEEK_API_KEY"]
            ?? ""
        let model =
            env["LLM_MODEL"]
            ?? env["DEEPSEEK_MODEL"]
            ?? "deepseek-v4-flash"
        let thinkingType = env["LLM_THINKING_TYPE"]

        return LLMAPIConfig(
            baseURL: URL(string: baseURLString) ?? URL(string: "https://api.deepseek.com")!,
            apiKey: apiKey,
            model: model,
            timeoutSeconds: 60,
            thinkingType: thinkingType
        )
    }
}
```

### 2. API key 管理策略

环境变量读取优先级：

```text
LLM_* 优先
DEEPSEEK_* 其次（兼容旧配置）
默认值最后
```

兼容说明：

```text
如果同时配置 LLM_* 和 DEEPSEEK_*，优先使用 LLM_*。
旧配置 DEEPSEEK_API_KEY / DEEPSEEK_BASE_URL / DEEPSEEK_MODEL 仍然可用，不会破坏已有配置。
```

推荐配置示例：

#### DeepSeek

```text
LLM_API_KEY = sk-你的 DeepSeek key
LLM_BASE_URL = https://api.deepseek.com
LLM_MODEL = deepseek-v4-flash
LLM_THINKING_TYPE = disabled
```

#### 其他 OpenAI-compatible 服务（阿里 DashScope / 其他）

```text
LLM_API_KEY = 你的兼容 API key
LLM_BASE_URL = 对应服务的 OpenAI-compatible base URL
LLM_MODEL = 对应模型名
```

如果该服务不支持 `thinking` 参数，则不要配置 `LLM_THINKING_TYPE`，此时请求体中不会发送 `thinking` 字段。

v0.2 第一阶段推荐方案：

```text
本地环境变量 / Xcode Scheme Environment Variables
```

也可以使用：

```text
Secrets.xcconfig
```

但必须保证：

```text
Secrets.xcconfig
*.xcconfig.local
```

加入 `.gitignore`。

禁止：

```swift
let apiKey = "sk-xxxxxxxx"
```

## 五、请求与响应 DTO

### 1. ChatCompletionRequest.swift

```swift
import Foundation

struct ChatCompletionRequest: Encodable {
    let model: String
    let messages: [ChatCompletionMessage]
    let stream: Bool
    let maxTokens: Int?
    let temperature: Double?
    let responseFormat: ResponseFormat?
    let thinking: ThinkingConfig?

    enum CodingKeys: String, CodingKey {
        case model
        case messages
        case stream
        case maxTokens = "max_tokens"
        case temperature
        case responseFormat = "response_format"
        case thinking
    }
}

struct ChatCompletionMessage: Codable {
    let role: String
    let content: String
}

struct ResponseFormat: Encodable {
    let type: String
}

struct ThinkingConfig: Encodable {
    let type: String
}
```

说明：

* 对话流式回复：`stream = true`
* 结构化提取：`stream = false`
* JSON 提取时可设置：

```swift
ResponseFormat(type: "json_object")
```

* **`maxTokens` 是防止模型回复过长或 JSON 被截断的关键字段：**
  * 对话流式回复建议 `maxTokens = 500` — 苏格拉底式追问每次只问 1-2 个问题，500 token 足够，同时避免模型一次性输出长篇方案破坏交互节奏。
  * JSON 结构化提取建议 `maxTokens = 1200` — JSON schema 包含 12 个字段 + 数组，1200 token 提供足够空间，同时防止输出被截断导致 JSON 解析失败。
  * 如果 API 返回的 `finish_reason == "length"`，说明输出被 `maxTokens` 截断，应抛错 fallback 而非强行 decode。
* **`thinking` 参数用于控制推理模式：**
  * `thinking` 是否发送由环境变量 `LLM_THINKING_TYPE` 控制。
  * 如果配置了 `LLM_THINKING_TYPE=disabled`，则请求体中传入 `ThinkingConfig(type: "disabled")` 关闭 thinking mode。
  * 如果未配置 `LLM_THINKING_TYPE`，则 `thinking` 传 `nil`，请求体中不发送该字段，以兼容不支持 thinking 的 OpenAI-compatible API。
  * v0.2 阶段建议为 DeepSeek 配置 `LLM_THINKING_TYPE=disabled`：优先保证速度、稳定性和可调试性。苏格拉底式追问和结构化提取不需要深度推理。
  * DeepSeek 当前模型可能默认启用 thinking mode，显式关闭避免额外延迟和不稳定。
  * 后续 v0.3 如果需要更强推理能力，可以配置 `LLM_THINKING_TYPE=enabled` 或不配置该项。

如果 API 不支持 `response_format` 或 `thinking`，则保留 prompt 约束兜底；如果 API 忽略这些字段（未知字段静默跳过），也不会报错。

### 2. ChatCompletionResponse.swift

```swift
import Foundation

struct ChatCompletionResponse: Decodable {
    let choices: [Choice]

    struct Choice: Decodable {
        let message: Message?
        let delta: Delta?
        let finishReason: String?

        enum CodingKeys: String, CodingKey {
            case message
            case delta
            case finishReason = "finish_reason"
        }
    }

    struct Message: Decodable {
        let role: String?
        let content: String?
    }

    struct Delta: Decodable {
        let role: String?
        let content: String?
    }
}
```

用途：

* 非流式提取：读取 `choices[0].message.content`
* 流式回复：读取 SSE 中每行 JSON 的 `choices[0].delta.content`
* **重要：** 非流式请求解码后必须检查 `choices[0].finishReason`。如果值为 `"length"`，说明输出被 `maxTokens` 截断，JSON 可能不完整，应抛出 `APIError.decodingFailed` 而非强行 decode。详见第七节 `completeJSON()` 示例。

## 六、API 错误设计

新增文件：

```text
Services/API/APIError.swift
```

```swift
import Foundation

enum APIError: Error, LocalizedError {
    case missingAPIKey
    case invalidURL
    case invalidResponse
    case httpStatus(Int, String)
    case decodingFailed
    case emptyResponse
    case networkFailed(Error)

    var errorDescription: String? {
        switch self {
        case .missingAPIKey:
            return "缺少 API Key，请检查本地配置。"
        case .invalidURL:
            return "API 地址无效。"
        case .invalidResponse:
            return "API 返回格式无效。"
        case .httpStatus(let code, let body):
            return "API 请求失败：HTTP \(code)。\(body)"
        case .decodingFailed:
            return "API 返回解析失败。"
        case .emptyResponse:
            return "API 返回为空。"
        case .networkFailed(let error):
            return "网络请求失败：\(error.localizedDescription)"
        }
    }
}
```

v0.2 只需要最小错误处理：

| 错误            | 行为                                       |
| ------------- | ---------------------------------------- |
| missingAPIKey | 不请求 API，fallback Mock                    |
| 401           | 提示 key 错误，fallback Mock                  |
| 429           | 提示限流，fallback Mock                       |
| 5xx           | fallback Mock                            |
| JSON 解析失败     | 结构化提取返回空 ExtractedFields 或 fallback Mock |
| 网络断开          | 不崩溃，fallback Mock                        |

## 七、API Client 设计

新增文件：

```text
Services/API/LLMAPIClient.swift
```

职责：

* 构造 request
* 添加 Authorization header
* 发送非流式请求
* 发送流式请求
* 解析 SSE
* 不直接操作 SwiftData
* 不直接更新 UI

建议接口：

```swift
import Foundation

final class LLMAPIClient {
    private let config: LLMAPIConfig
    private let session: URLSession

    init(config: LLMAPIConfig = .loadFromEnvironment(),
         session: URLSession = .shared) {
        self.config = config
        self.session = session
    }

    func streamChat(messages: [ChatCompletionMessage]) -> AsyncThrowingStream<String, Error> {
        AsyncThrowingStream { continuation in
            Task {
                do {
                    guard config.isValid else {
                        throw APIError.missingAPIKey
                    }

                    var request = URLRequest(url: config.chatCompletionsURL)
                    request.httpMethod = "POST"
                    request.setValue("application/json", forHTTPHeaderField: "Content-Type")
                    request.setValue("Bearer \(config.apiKey)", forHTTPHeaderField: "Authorization")
                    request.timeoutInterval = config.timeoutSeconds

                    let body = ChatCompletionRequest(
                        model: config.model,
                        messages: messages,
                        stream: true,
                        maxTokens: 500,
                        temperature: 0.7,
                        responseFormat: nil,
                        thinking: config.thinkingType.map { ThinkingConfig(type: $0) }
                    )

                    request.httpBody = try JSONEncoder().encode(body)

                    let (bytes, response) = try await session.bytes(for: request)

                    if let http = response as? HTTPURLResponse,
                       !(200...299).contains(http.statusCode) {
                        throw APIError.httpStatus(http.statusCode, "")
                    }

                    var emittedTokenCount = 0

                    for try await line in bytes.lines {
                        if line.hasPrefix("data: ") {
                            let dataString = String(line.dropFirst(6))
                            if dataString == "[DONE]" {
                                break
                            }

                            guard let data = dataString.data(using: .utf8) else { continue }
                            let decoded = try? JSONDecoder().decode(ChatCompletionResponse.self, from: data)
                            let token = decoded?.choices.first?.delta?.content

                            if let token, !token.isEmpty {
                                continuation.yield(token)
                                emittedTokenCount += 1
                            }
                        }
                    }

                    // 0 token 检测：如果流正常结束但没有任何 token，视为空响应
                    if emittedTokenCount == 0 {
                        throw APIError.emptyResponse
                    }

                    continuation.finish()
                } catch {
                    continuation.finish(throwing: error)
                }
            }
        }
    }

    func completeJSON(messages: [ChatCompletionMessage]) async throws -> String {
        guard config.isValid else {
            throw APIError.missingAPIKey
        }

        var request = URLRequest(url: config.chatCompletionsURL)
        request.httpMethod = "POST"
        request.setValue("application/json", forHTTPHeaderField: "Content-Type")
        request.setValue("Bearer \(config.apiKey)", forHTTPHeaderField: "Authorization")
        request.timeoutInterval = config.timeoutSeconds

        let body = ChatCompletionRequest(
            model: config.model,
            messages: messages,
            stream: false,
            maxTokens: 1200,
            temperature: 0.2,
            responseFormat: ResponseFormat(type: "json_object"),
            thinking: ThinkingConfig(type: "disabled")
        )

        request.httpBody = try JSONEncoder().encode(body)

        let (data, response) = try await session.data(for: request)

        if let http = response as? HTTPURLResponse,
           !(200...299).contains(http.statusCode) {
            let bodyText = String(data: data, encoding: .utf8) ?? ""
            throw APIError.httpStatus(http.statusCode, bodyText)
        }

        let decoded = try JSONDecoder().decode(ChatCompletionResponse.self, from: data)

        // finish_reason == "length" 说明输出被 maxTokens 截断，JSON 可能不完整
        if decoded.choices.first?.finishReason == "length" {
            throw APIError.decodingFailed
        }

        guard let content = decoded.choices.first?.message?.content,
              !content.isEmpty else {
            throw APIError.emptyResponse
        }

        return content
    }
}
```

### 2. ExtractionPromptTemplates.swift

Services/Prompts/ExtractionPromptTemplates.swift
```

职责：

* 把最近对话转成 ExtractedFields JSON
* 只输出 JSON
* 不输出解释

```swift
enum ExtractionPromptTemplates {
    static func systemPrompt() -> String {
        """
        你是一个设计项目结构化信息提取器。

        你的任务是从用户和 AI 的对话中提取设计项目信息，并输出严格 JSON。

        你的最终输出必须是一个可被 JSONDecoder 直接解析的 JSON object。
        不要输出任何自然语言、Markdown、代码块标记或额外解释。
        不要用 ```json 包裹。
        如果某个字段没有从对话中明确出现，请填 null，不要推测或编造。
        不要补充用户没有表达过的信息。

        JSON schema:
        {
          "targetUser": string | null,
          "painPoint": string | null,
          "useScenario": string | null,
          "coreValue": string | null,
          "differentiation": string | null,
          "boundaryItems": [
            {
              "content": string,
              "isIncluded": boolean
            }
          ] | null,
          "mvpFeatures": string | null,
          "technicalModules": string | null,
          "interactionFlow": string | null,
          "operationLogic": string | null,
          "hardConstraints": string | null,
          "successMetrics": [
            {
              "metric": string,
              "target": string,
              "measurement": string | null
            }
          ] | null,
          "risks": [
            {
              "description": string,
              "probability": number,
              "impact": number,
              "mitigation": string | null
            }
          ] | null,
          "milestones": string | null
        }
        """
    }

    static func userPrompt(
        messages: [ChatPayloadMessage],
        existing: DesignBriefSnapshot?
    ) -> String {
        """
        已有设计简报：
        \(existingBriefText(existing))

        最近对话：
        \(messagesText(messages))

        请基于最近对话，提取新的字段。
        只返回 JSON。
        """
    }

    private static func existingBriefText(_ brief: DesignBriefSnapshot?) -> String {
        guard let brief else { return "暂无。" }

        return """
        targetUser: \(brief.targetUser ?? "null")
        painPoint: \(brief.painPoint ?? "null")
        useScenario: \(brief.useScenario ?? "null")
        coreValue: \(brief.coreValue ?? "null")
        differentiation: \(brief.differentiation ?? "null")
        mvpFeatures: \(brief.mvpFeatures ?? "null")
        technicalModules: \(brief.technicalModules ?? "null")
        interactionFlow: \(brief.interactionFlow ?? "null")
        operationLogic: \(brief.operationLogic ?? "null")
        hardConstraints: \(brief.hardConstraints ?? "null")
        milestones: \(brief.milestones ?? "null")
        """
    }

    private static func messagesText(_ messages: [ChatPayloadMessage]) -> String {
        messages
            .suffix(12)
            .map { "\($0.role): \($0.content)" }
            .joined(separator: "\n")
    }
}
```

> **关于 `response_format` 与 prompt 约束的双重保障：**
>
> 即使请求中设置了 `response_format: {"type": "json_object"}`，prompt 中仍然必须明确要求模型输出 JSON。原因：
>
> * 部分 OpenAI-compatible API 对 `response_format` 的支持不完整，可能忽略该字段；
> * 即使支持，部分模型在 `response_format: json_object` 下仍可能出现空白输出、非 JSON 输出或长时间等待；
> * prompt 级别的约束是兜底，不依赖单一机制。
>
> 因此 v0.2 同时使用 `response_format` + prompt 硬约束 + `cleanJSON()` 清理，三层防护。

## 九、LiveLLMService 实现方案

修改文件：

```text
Services/Live/LiveLLMService.swift
```

目标：

* 使用 LLMAPIClient
* 拼接 system prompt + context prompt + 历史消息
* 调用 streamChat
* 失败 fallback 到 MockLLMService
* 不直接操作 SwiftData

```swift
final class LiveLLMService: LLMServiceProtocol {
    private let client: LLMAPIClient
    private let fallback = MockLLMService()

    init(client: LLMAPIClient = LLMAPIClient()) {
        self.client = client
    }

    func streamChat(
        messages: [ChatPayloadMessage],
        briefSnapshot: DesignBriefSnapshot?,
        currentStage: ProgressStageSnapshot?
    ) -> AsyncThrowingStream<String, Error> {
        let apiMessages = buildMessages(
            messages: messages,
            briefSnapshot: briefSnapshot,
            currentStage: currentStage
        )

        let liveStream = client.streamChat(messages: apiMessages)

        return AsyncThrowingStream { continuation in
            Task {
                do {
                    for try await token in liveStream {
                        continuation.yield(token)
                    }
                    continuation.finish()
                } catch {
                    // Debug 可观测性：打印 fallback 原因
                    print("[LiveLLMService] Live failed, fallback to Mock: \(error)")

                    let fallbackStream = fallback.streamChat(
                        messages: messages,
                        briefSnapshot: briefSnapshot,
                        currentStage: currentStage
                    )

                    for try await token in fallbackStream {
                        continuation.yield(token)
                    }

                    continuation.finish()
                }
            }
        }
    }

    private func buildMessages(
        messages: [ChatPayloadMessage],
        briefSnapshot: DesignBriefSnapshot?,
        currentStage: ProgressStageSnapshot?
    ) -> [ChatCompletionMessage] {
        var result: [ChatCompletionMessage] = []

        result.append(ChatCompletionMessage(
            role: "system",
            content: SocraticPromptTemplates.systemPrompt()
        ))

        result.append(ChatCompletionMessage(
            role: "system",
            content: SocraticPromptTemplates.contextPrompt(
                brief: briefSnapshot,
                currentStage: currentStage
            )
        ))

        result.append(contentsOf: messages.suffix(12).map {
            ChatCompletionMessage(role: $0.role, content: $0.content)
        })

        return result
    }
}
```

## 十、LiveStructuredExtractor 实现方案

修改文件：

```text
Services/Live/LiveStructuredExtractor.swift
```

目标：

* 非流式调用 API
* prompt 要求模型只输出 JSON
* 解码为 ExtractedFields
* 解码失败 fallback Mock
* 不中断对话主流程

````swift
final class LiveStructuredExtractor: StructuredExtractorProtocol {
    private let client: LLMAPIClient
    private let fallback = MockStructuredExtractor()

    init(client: LLMAPIClient = LLMAPIClient()) {
        self.client = client
    }

    func extract(
        from messages: [ChatPayloadMessage],
        existing: DesignBriefSnapshot?
    ) async throws -> ExtractedFields {
        let apiMessages = [
            ChatCompletionMessage(
                role: "system",
                content: ExtractionPromptTemplates.systemPrompt()
            ),
            ChatCompletionMessage(
                role: "user",
                content: ExtractionPromptTemplates.userPrompt(
                    messages: messages,
                    existing: existing
                )
            )
        ]

        do {
            let jsonText = try await client.completeJSON(messages: apiMessages)
            let cleaned = cleanJSON(jsonText)
            guard let data = cleaned.data(using: .utf8) else {
                throw APIError.decodingFailed
            }
            return try JSONDecoder().decode(ExtractedFields.self, from: data)
        } catch {
            // Debug 可观测性：打印 fallback 原因
            print("[LiveStructuredExtractor] Live extraction failed, fallback to Mock: \(error)")
            return try await fallback.extract(from: messages, existing: existing)
        }
    }

    private func cleanJSON(_ text: String) -> String {
        text
            .replacingOccurrences(of: "```json", with: "")
            .replacingOccurrences(of: "```", with: "")
            .trimmingCharacters(in: .whitespacesAndNewlines)
    }
}
````

> **说明：** `completeJSON()` 内部已处理 `finish_reason == "length"` 的情况（抛出 `APIError.decodingFailed`），因此 `LiveStructuredExtractor` 收到该错误后会进入 `catch` 分支 fallback 到 Mock，不需要额外处理。
